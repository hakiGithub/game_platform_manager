# 01: Git Bash 热部署选中 Windows Store python3 占位程序

Status: resolved
Type: bug
来源: 2026-10-20 L4D2 地图修复热部署

## 现象

在 Windows 主机上通过 PowerShell 7 调用：

```powershell
& 'C:\Program Files\Git\bin\bash.exe' scripts/deploy-plugin.sh --skip-frontend
```

脚本完成插件 JAR 构建后，在登录后端阶段退出：

```text
[19:58:20] 使用构建产物: .../plugin-l4d2-core-1.0.0-SNAPSHOT.jar
[19:58:20] 登录后端...
```

此时插件尚未卸载或覆盖，后端继续正常运行。

## 根因

`scripts/deploy-plugin.sh` 使用：

```bash
PYTHON_BIN="$(command -v python3 || command -v python || true)"
```

Git Bash 的 PATH 中 `python3` 先解析到：

```text
/c/Users/haki/AppData/Local/Microsoft/WindowsApps/python3
```

这是 Windows Store 的应用执行别名，在当前环境不能可靠运行 JSON 解析。
同一环境中可用的真实解释器为：

```text
/c/Users/haki/AppData/Local/Programs/Python/Python313/python
```

## 期望

- 热部署脚本优先选择实际可执行的 Python 解释器。
- 候选解释器必须通过最小可执行性探测，而不是只凭 `command -v` 接受。
- Windows Git Bash 默认选择可用的 `python`；WSL 无 `python` 时仍可回退到 `python3`。
- 探测失败时给出明确错误，不进入登录和插件卸载阶段。
- 增加回归测试，防止再次把 `python3` 的解析顺序固定在可用 `python` 之前。
