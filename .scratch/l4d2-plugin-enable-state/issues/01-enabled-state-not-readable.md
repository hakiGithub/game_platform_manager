# 01: 启用成功但插件列表仍显示已禁用

Status: resolved
Type: bug
来源: 用户反馈（2026-10-21）

## 现象

已安装插件页面中的插件全部显示“已禁用”。点击单个“启用”或“批量启用”
后接口返回成功，但刷新列表状态不变。

真实请求：

```http
POST /api/plugin/l4d2/plugins/enable-load?instanceId=97&pluginName=...
```

返回：

```json
{"code":200,"message":"操作成功","data":null}
```

随后查询 `GET /api/plugin/l4d2/plugins/list?instanceId=97`，目标插件仍为：

```json
{"status":"disabled","enableTime":null}
```

## 根因候选与证据

- 文件复制实际成功，目标 `.smx` 已出现在游戏目录中。
- `.enabled_plugins.yaml` 已追加新插件记录，说明接口链路执行完成。
- 同一 YAML 中大量历史中文插件名已损坏为问号，例如
  `自选-排行榜插件...` 变成 `???-????????...`。
- `EnabledPluginsService.loadYaml` 显式按 UTF-8 读取，但
  `saveYaml` 调用了不带字符集的 `writeTextFile`，落到 JVM 默认字符集。
- 名单读取后再整体写回会把损坏名称继续传播，列表按目录名匹配时失配，
  最终全部回落为 `disabled`。

## 期望

- 清单读写固定使用 UTF-8。
- 保存时不能把已损坏的名称当作有效插件名。
- 对历史损坏条目，从已有 `plugins_store` 目录中选择唯一可识别名称恢复。
- 无法唯一恢复的损坏条目应跳过，不得产生错误启用状态或覆盖其他记录。
- 单插件和批量启用都通过同一修复后的登记逻辑回读为 `enabled`。
