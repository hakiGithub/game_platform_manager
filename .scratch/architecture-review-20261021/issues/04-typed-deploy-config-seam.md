# 04 — 部署配置是无类型 Map，同一份数据被组装两遍且规则不同

**Status:** done
**Type:** task
**来源:** 架构评审 2026-10-21（候选 4，强度 Worth exploring）

## 现象

`DeployAdapter` 的全部 18 个方法都接 `Map<String,Object> config`。
「config 里必须有哪些键」这件事不住在任何地方——每个适配器自己在代码里
`getConfigString(config, "image", "")` 猜，缺键就静默用默认值。

同一份实例数据被**组装两遍**，且两遍规则不同：

| 站点 | 行 | 做了什么 |
|---|---|---|
| `InstanceServiceImpl.buildDeployConfig` | :714-803 | 6 步合并：游戏元数据模板 &rarr; configInfo（跳过 `database`）&rarr; portConfig &rarr; installPath/instanceId/gameCode &rarr; runtimeMetadata 提升 &rarr; image:tag 拼接 |
| `DeployService.getInstanceConfig` | :809-822 | 只合并 configInfo + portConfig，共 8 行 |

`buildDeployConfig` 内部还有 `promoteMetadataIfAbsent`，按 key 逐个手写提升
（`projectName` / `workDir` / `containerName` / `shortname` / `serviceName`）——
加一个 runtime 字段就要回来改这个方法。

`InstanceServiceImpl` 一个文件里 20 处调用 `buildDeployConfig`，另 11 处在 `DeployService`。

## 根因

部署配置的**形状**没有 owner。它是 DB 三列（`configInfo` / `portConfig` /
`runtimeMetadata`）加游戏元数据模板的合成产物，但合成规则散落在两个 service 里，
消费方又按字符串键各自解释。缺键不报错，所以契约只能靠约定维持。

## 修复建议

一个 module 拥有配置组装，向适配器交出类型化记录：

```
DeployConfig(installPath, workDir, projectName, containerName, serviceName,
             shortname, image, ports, env, database, ...)
DeployConfigAssembler.assemble(GameInstance) -> DeployConfig
```

- `DeployService.getInstanceConfig` 删除，改走同一组装器。
- runtimeMetadata 提升改为按声明列表遍历，不再逐 key 手写。
- 适配器方法签名从 `Map` 改为 `DeployConfig`（或保留 Map 外壳、内部即类型化对象）。

## 验收

1. 实例配置只经一个入口组装；`getInstanceConfig` 删除。
2. 适配器不再用字符串键猜配置，缺必需键时编译期或启动期即失败。
3. `buildDeployConfig` 现有行为不变（含 `database` 跳过与 `image:tag` 拼接），
   现有 `InstanceServiceImplTest` 全绿。
4. 新增 runtimeMetadata 字段只需改声明列表，不改组装逻辑。

## 关联

- **ADR-0008**：插件通过 `getDeployConfigs()` 把配置节合并进来，合并后的产物
  仍是 Map。本票只类型化主应用侧，**插件侧 seam 保持 Map 不变**，否则与 ADR-0008 冲突。
- 与票 01 天然衔接：合并后的 Compose module 正好以 `DeployConfig` 为入参。
