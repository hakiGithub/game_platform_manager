# 02 — 部署方式词汇表无 owner，前端已两处拼写不一致

**Status:** needs-triage
**Type:** task
**来源:** 架构评审 2026-10-21（候选 2，强度 Strong）

## 现象

ADR-0005 已把实例状态词汇表收口：后端 `DeployAdapter.InstanceStatus` 是唯一文本源，
前端 `utils/instanceStatus.js` 只留 UI 元数据（颜色、图标、活跃集合）。

但**部署方式**（`DeployType` 的四个 code）没有享受同一待遇，前端多处各自重新建表：

| 站点 | 行 | 内容 |
|---|---|---|
| `views/instance/detail.vue` | :238 | `"linuxgsm-docker": "LinuxGSM Docker 部署"`（完整文案表） |
| `views/instance/detail.vue` | :249 | `"linuxgsm-docker": "danger"`（tag 颜色表） |
| `views/instance/detail.vue` | :260 | `"linuxgsm-docker": "LGSM Docker"`（简短文案表，第三张） |
| `views/game/index.vue` | :346 | `"linuxgsm-docker": { label: "LinuxGSM Docker", type: "danger" }` |
| `components/docker/AdoptInstanceDialog.vue` | :113 | `["docker","docker-compose","linuxgsm-docker"]`（可认领集合） |
| `views/instance/deploy.vue` | :181, :713, :1332, :1626 | 选项表 + 四处 Docker 类判断数组 |

同一事实的**两种拼写已经并存**：`detail.vue` 用「LinuxGSM Docker 部署」，
`game/index.vue` 用「LinuxGSM Docker」。同一个 key、同一个枚举，UI 上不一致。

## 根因

`DeployType` 虽是后端枚举，但前端没有一个 module 认领它。
ADR-0005 的模式（后端出文本、前端留 UI 元数据）没有套用到部署方式上，
于是每个视图按自己需要各建一张表，表与表之间没有约束。

## 修复建议

按 `instanceStatus.js` 的同形做法，建一个部署方式词汇表 module：

```
deployTypeLabels: code -> { label, tagType, short }
```

- 文案以 `DeployType.getDescription()` 为权威（后端已提供中文文本）。
- 前端只保留 UI 元数据（tag 颜色、简短别名）。
- Docker 类判断（`["docker","docker-compose","linuxgsm-docker"]`）收敛为一个谓词，消除五处重复数组。

## 验收

1. 部署方式文案只有一处定义，与 `DeployType.getDescription()` 一致。
2. `detail.vue` 的三张表、`game/index.vue` 的表合并为一个 module。
3. Docker 类判断收敛为一个谓词，`deploy.vue` 五处数组删除。
4. 有单测覆盖全部四个 code 的 label/tagType/short，并断言未知 code 的兜底行为。
5. `AdoptInstanceDialog` 的集合改由该谓词派生（或显式引用，并说明为何与谓词不同）。

## 关联

- 与票 03 同属「词汇表无 owner」一族，但作用于不同枚举，可独立进行。
- 与 ADR-0005 是同一模式的延伸，不重开决策。
