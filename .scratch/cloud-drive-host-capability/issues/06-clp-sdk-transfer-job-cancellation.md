# 06: clp-sdk 转存超时后无法取消底层 Job

Status: ready-for-human
Type: enhancement
来源: CloudDriveService SDK 超时契约核对（2026-10-20）

## 现象

`CloudDriveExecutor.transfer` 在等待转存 Job 超时后会抛出业务异常并保留 `jobId`，
但 clp-sdk 没有公开的 Job 取消 API，底层转存作业可能继续在网盘侧执行。
当前 ADR-0024 仍写着“超时则尽力取消底层 Job”，与可交付能力不一致。

## 期望

- 明确 SDK 是否提供取消转存 Job 的能力及其幂等语义。
- 若提供，宿主 `CloudDriveExecutor.transfer` 超时时应调用取消，并返回取消结果。
- 若取消失败，异常必须保留 `jobId`、失败原因和“底层作业可能继续”的说明。
- 取消能力实现前，平台与服务契约只承诺“超时抛错 + 返回 jobId”，不承诺远端停止。

## 验收

- [ ] clp-sdk 提供经测试的转存 Job 取消接口，或在 ADR 中明确永久不支持。
- [ ] 超时路径覆盖“取消成功、取消失败、Job 已完成”三种终态。
- [ ] 调用方能够根据异常/JOB ID 查询或重试，不把远端未停止误报成已取消。
- [ ] ADR-0024、CloudDriveService Javadoc 与实现语义一致。

## Out of scope

- 改变 L4D2 任务中心的取消状态机。
- 修改云盘目录浏览与起始目录寻址。
- 引入新的异步 Job 双轨体系。
