# 07: Aliyun/Xunlei 文件夹 ID 起始目录无法穿透 SDK mount 归一化

Status: ready-for-human
Type: bug
来源: ticket 05 cloud189 路径寻址修复后的 provider 契约核对（2026-10-20）
Blocked by: external SDK `cloud_list_platform` 提供 ID 型 provider 的安全 mount root 契约

## 现象

ticket 05 已把平台目录浏览统一为路径寻址，并在应用起始目录时按路径逐级列目录解析出
provider 原生文件夹 ID。cloud189 路径可走通，但 Aliyun/Xunlei 仍无法安全把该 ID 用于
默认挂载：

- `MountService.createMount(accountId, mountPath, rootPath)` 对非空 `rootPath` 执行
  `DirectoryRef.of(rootPath).path()`，任何 ID 字符串都会被加前导斜杠并保存为路径。
- 只有 cloud189 `Cloud189Client.rootFolderId()` 会把 `/-13` 这类“斜杠 + 数字”还原为 ID。
- AliyunProvider/XunleiProvider 的 `resolveId()` 只从 `settings.rootFolderId` 种子根解析路径；
  没有公开的“文件夹 ID → 已校验 mount root”解析 API，也没有 ID 型 mount root 表示。

## 复现/契约证据

外部 SDK（只读核对，未修改）：

- `D:\program\ai\cloud_list_platform\clp-core\src\main\java\com\haki\clouddrive\core\mount\MountService.java`
  `createMount` 第 36 行：`rootPath == null || rootPath.isBlank() ? "/" : DirectoryRef.of(rootPath).path()`。
- `clp-provider-cloud189\...\Cloud189Client.java` 第 110-117 行：仅 cloud189 对
  `/` + 纯数字串剥斜杠还原 ID。
- `clp-provider-aliyun\...\AliyunProvider.java` 第 85、299 行：
  `idByPath.put("/", settings.rootFolderId())`，ID 寻址从 settings 种子根开始。
- `clp-provider-xunlei\...\XunleiProvider.java` 第 82、377 行：同上。
- `clp-sdk\...\CloudDriveClient.java` 第 243 行：公开 API 只有
  `createMount(accountId, mountPath, rootPath)`，没有 ID/路径双语义入口。

## 期望

- SDK 明确提供 ID 型 provider 的“文件夹 ID → 已校验 mount root”契约，或让
  `createMount` 接受结构化 root（路径 / provider 原生 ID）。
- 在 SDK 契约落地前，平台不得把 Aliyun/Xunlei 的 ID 字符串伪装成路径写入 mount；
  应显式拒绝不安全的 ID 型起始目录，或保持账号根并在 UI/API 标注能力边界。
- 增加 SDK 契约测试，覆盖路径型 provider、cloud189 数字 ID、Aliyun/Xunlei ID 根三种语义。

## 验收

- [ ] Aliyun 或 Xunlei 以子目录 ID 作为起始目录后，默认挂载的 list/download 可正常寻址。
- [ ] 不再出现 `/<id>/...` 形式的错误路径寻址。
- [ ] SDK 契约测试覆盖 ID 型 mount root，且平台侧回归测试覆盖解析失败/能力降级路径。
- [ ] ticket 05 的路径浏览契约与 ADR-0024 的 provider 边界说明保持一致。
