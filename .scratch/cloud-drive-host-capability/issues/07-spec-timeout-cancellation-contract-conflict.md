# 07: 云盘 spec 的超时取消表述与 ADR/实现冲突

Status: resolved
Type: decision
来源: 票据 06 的 clp-sdk 取消能力源码核对（2026-10-20）

## 问题

云盘能力 spec 的关键决策第 7 条仍写着“超时尽力取消底层 Job”：

- `.scratch/cloud-drive-host-capability/spec.md:19`

但当前 ADR-0024、`CloudDriveService.transfer` Javadoc 与 `CloudDriveExecutor.transfer`
实现已经统一为：

- 超时抛出业务异常并保留 `jobId`；
- 不承诺远端取消；
- 底层作业可能继续在网盘侧执行。

本地 `clp-sdk` 源码也没有公开的 Job 取消 API、取消状态或 Provider 取消原语。因此
spec 的“尽力取消”是历史愿望表述，不是当前可交付契约。

## 需要决定

已按当前交付边界裁决：

1. 接受当前能力边界，修正 spec 第 19 行为“超时抛错 + 返回 `jobId`，底层作业可能继续”。
2. 不把“新增 SDK 取消能力”塞进本仓库票；若未来产品明确要求取消，先在
   `cloud_list_platform` 设计 Provider/SDK 契约、幂等语义、各 Provider 支持矩阵与测试，
   再集成回本仓库。
