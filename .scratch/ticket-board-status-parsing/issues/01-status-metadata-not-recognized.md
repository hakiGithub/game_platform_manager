# 01 — Ticket 看板漏认粗体与带说明的 Status

Status: resolved
Type: bug
来源: 2026-10-20 triage 看板复核

## 现象

`build-tickets.mjs` 只解析 `Status:` / `Type:` 等纯文本元数据行，不识别
Markdown 粗体写法 `**Status:**`，也不会把 `done（2026-09-10 修复）` 这类
带说明的状态归入已关闭状态。

结果是架构复审 01-09 与 ui-e2e-automation 01-09 被错误显示为
`open (review)` / `open (unregistered)`，backlog 中已修复的 02/03/04 也仍
显示为目录开放。看板因此多报了一批不存在的待办票，影响 triage 范围判断。

## 根因

- `parseMetadata` 的状态正则只接受行首裸 `Status:`。
- `closed` 只用完整字符串匹配 `done` / `resolved` 等值，无法识别状态值后的
  中文说明或括号。
- `**Type:**`、`**Blocked by:**` 等粗体元数据也会一并漏读。

## 修复

- 元数据解析兼容可选的 Markdown 粗体标记。
- 关闭状态按首个状态词识别，兼容 `done（说明）`、`resolved - note` 等写法。
- 重建 `tickets.json` / `index.html`，确认误报的已完成票回到已关闭分栏。

## 验收

- [x] `Status: done（说明）` 被识别为已关闭。
