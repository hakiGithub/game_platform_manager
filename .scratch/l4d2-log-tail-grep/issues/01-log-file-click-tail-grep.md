# 01: 日志文件点击不加载且搜索未走远端 grep

Status: resolved
Type: bug
来源: 用户反馈（2026-10-20）

## 现象

在 L4D2 日志页点击 `L261020.log` 后，右侧标题仍显示 `errors_20261018.log`，内容为空，
连接状态为“未连接”。当前前端使用无法附加 JWT `Authorization` 头的 `EventSource`，
且文件选择状态在启动早退时不会更新。搜索框只过滤浏览器已经加载的行。

## 期望

- 点击任一日志文件后，标题、内容和连接状态对应新文件。
- 初次加载使用远端 `tail -n N -- <file>`，只读取末尾若干行。
- 搜索使用远端 `tail -n N -- <file> | grep -F -- <pattern>`，无匹配时显示明确空态。
- 新内容轮询和搜索请求使用带鉴权的 HTTP API，快速切换文件时旧响应不得覆盖新选择。
- 路径与搜索词经过安全转义，不开放任意 shell 执行。

## 验收

- [x] 点击文件后标题立即更新，内容请求携带正确文件名。
- [x] Native 与 Docker 路由都执行 `tail -n` / `grep -F` 语义命令。
- [x] 搜索词中的空格、引号、`$`、管道字符不会改变命令结构。
- [x] 无匹配时显示明确空态，不误显示旧文件内容。
- [x] 快速切换文件时旧响应不会覆盖新文件。
- [x] 后端与前端回归测试、插件构建通过。

## Comments

- 2026-10-20：日志读取改为带 JWT 的 HTTP 短轮询，初始加载远端 `tail -n 2000 -- <file>`；
  Native 与 Docker 路由统一执行 `tail`、可选 `grep -F`，并通过 Base64 传输避免 GBK 日志损坏。
- 2026-10-20：文件选择会立即更新标题并重置搜索；请求序号防止快速切换时旧响应覆盖新文件；
  搜索后的轮询继续携带当前关键字，避免 grep 结果被无过滤内容覆盖。
- 验证：`InstanceFileServiceImplTest` 通过；插件前端 `Logs.test.ts` 3 个用例通过；
  `plugin-l4d2-core` 打包与插件前端生产构建通过。
