# 02 — stale PID 触发必填参数绑定错误，后端重启脚本无法开始部署

Status: done
Type: bug
来源: 2026-10-20 集成分支全栈重部署人工验证

## 现象

在集成分支执行：

```powershell
pwsh -NoProfile -File scripts/rebuild-restart-all.ps1 -FrontendPort 3002
```

后端重启阶段在停止旧进程时立即失败：

```text
[ERROR] 后端脚本执行失败: Cannot bind argument to parameter 'ProcessInfo' because it is null.
```

上层随即报告后端重启失败，后端编译、插件打包和启动都没有执行。

## 复现路径

1. 停止现有后端，确保 `8080` 没有监听。
2. 让 `backend/logs/game-platform-manager.pid` 保留一个已不存在的 PID。
3. 执行 `backend/scripts/rebuild-restart.ps1` 或全栈入口。
4. 停止旧进程逻辑通过 stale PID 调用 `Get-BackendProcessByPid`。
5. 目标进程不存在时 `Get-CimInstance` 返回 `$null`，随后传给必填参数
   `Test-BackendJavaProcess -ProcessInfo`，PowerShell 在函数体执行前抛参数绑定错误。

本次现场 PID 文件为 `4780`，启动器 PID 文件为 `8440`，两者进程均已不存在；
`8080` 也无监听。

## 期望

- stale PID 是正常停止场景，必须安全返回“未发现运行中的后端进程”，不得抛异常。
- `Test-BackendJavaProcess` 对不存在的进程返回 `false`，由调用方按无进程处理。
- `Get-BackendProcessByPid` 在进程不存在时不调用必填参数校验或显式跳过。
- 回归测试覆盖 stale PID、空进程结果和正常 Java 识别。
- 修复后全栈重部署能够继续执行编译、插件构建、打包、启动与健康检查。

## 验收

- [ ] 进程识别测试覆盖上述空值边界。
