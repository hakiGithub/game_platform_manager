# 05: 云盘中转下载取消可能被包装成失败

Status: done
Type: bug
来源: L4D2 云盘安装真实任务与代码复核（2026-10-20）

## 现象

RELAY 通道通过 `ProgressOutputStream` 在写入过程中检查 `TaskContext.isCancelled()` /
`isTimeout()`，并以 `CancelledSignal` 中断。但该异常会先穿过宿主
`CloudDriveExecutor.download()` 的通用异常包装，变成 `BusinessException`；
随后 `CloudInstallService.installRelay()` 的通用 `catch (Exception)` 又将其包装成
`L4D2PluginException`。

已有的取消验证只在下载前或下载流之外触发，尚未证明“真实流式下载中取消”会落为
`CANCELLED`。如果取消发生在上传调用内部，现有任务上下文已取消但宿主异常仍可能被
记录为 `FAILED`。

## 复现路径

1. 启动一个 RELAY 云盘安装任务，使任务处于平台中转下载阶段。
2. 在 `cloudDriveService.download()` 写入部分数据后取消任务。
3. 宿主下载层因流写入异常返回业务异常。
4. 观察任务中心和下载记录终态。

## 实际行为

取消信号可能被两层通用异常处理包装，最终记录为 `FAILED`，错误信息类似
“中转安装失败 … 下载失败 … 任务已取消”。

## 期望

- 只要任务上下文已取消，下载阶段抛出的异常必须归并为 `CANCELLED`。
- 只要任务上下文已超时，下载阶段抛出的异常必须归并为超时终态，不显示为普通失败。
- 真正的下载错误仍落为 `FAILED`，并保留可诊断的错误信息。
- 部分写入的临时文件仍会被清理。

## 验收

- [ ] 测试 mock 云盘下载写入部分数据后抛异常，同时任务上下文为已取消，最终记录为
  `CANCELLED` 而不是 `FAILED`。
- [ ] 同等场景下任务上下文为已超时，最终记录为超时语义而不是普通失败。
- [ ] 非取消、非超时的下载异常仍记录为 `FAILED`。
- [ ] RELAY 模式、进度和临时文件清理行为不回归。

## Out of scope

- 改变任务中心通用状态机。
- 直连下载（PatchInstall）链路的取消语义。

### 2026-10-20 Triage 结论

**分类：** bug
**状态：** ready-for-agent

已用服务层测试复现：云盘下载在写出一段数据后抛异常，同时任务上下文变为已取消/已超时，
`installRelay` 会把异常包装成 `L4D2PluginException`，外层 `execute` 再走通用失败分支，
使下载记录落为 `FAILED`。根因是下载阶段没有在通用异常边界重新检查任务上下文。

### 2026-10-20 实施结果

- `installRelay` 的通用异常分支先检查 `context.isCancelled()` / `context.isTimeout()`，
  命中时统一抛出 `CancelledSignal`，由外层记录 `CANCELLED`。
- 非取消、非超时的下载异常仍包装为 `L4D2PluginException`，记录 `FAILED`。
- 新增 3 条服务层回归测试：取消后宿主异常、超时后宿主异常、普通下载异常。
- 定向测试 `CloudInstallServiceTest`：5/5 通过。
