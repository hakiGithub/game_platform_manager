# 05: dnf-tw 部署时 Compose 变量未传到确认页和部署载荷

Status: done
Type: bug
来源: 用户部署反馈（2026-10-19）

## 现象

在部署 dnf-tw（`dnf_tw` / Docker Compose）时，用户已在“配置参数”步骤修改 Compose 变量：

- MySQL 端口：`3010`
- 数据库 root 密码：自定义值
- 对外 IP：`192.168.111.253`

但进入“确认部署”步骤后，变量摘要显示为：

- MySQL 端口：`3000`
- 数据库 root 密码：掩码，无法看出是否为用户值
- 对外 IP：`127.0.0.1`

即确认页展示的是变量默认值，而不是用户在配置步骤填写的值。用户要求改后的变量能够带到下一步，并按该值完成部署。

## 复现步骤

1. 打开实例部署向导，选择 dnf-tw、Docker Compose 和目标主机。
2. 进入“配置参数”步骤。
3. 将 Compose 变量改为 `MYSQL_PORT=3010`、自定义 `DNF_DB_ROOT_PASSWORD`、`PUBLIC_IP=192.168.111.253`。
4. 点击“下一步”，进入“环境校验”，再进入“确认部署”。
5. 查看“Compose 变量”摘要。

## 实际行为

确认页显示 `MYSQL_PORT=3000`、`PUBLIC_IP=127.0.0.1`，与配置步骤的输入不一致。
后端 `generateEnvFileContent` 从 `configInfo` 顶层读取 Compose 变量；若提交载荷也未采用用户值，生成的 `.env` 与实例配置会继续使用默认值，导致部署结果不符合用户配置。

## 期望行为

- 配置步骤修改后的 Compose 变量在确认页原样展示，密码仍以掩码展示。
- “开始部署”提交的 `configInfo` 使用用户修改后的变量值，而不是 yml 默认值。
- 生成的 `.env` 与实例 `config_info` 中的变量值一致，部署使用该 `.env`。
- 未修改的变量继续使用 yml 默认值，隐藏变量 `GATE_AES_KEY` 不会被可见表单覆盖或丢失。
- 切换步骤、返回上一步再继续时，已修改值不丢失；切换游戏或部署方式时不沿用上一组变量。

## 初步定位

前端变量输入存在两处状态源：

- `deploy.vue` 的 `deployVariablesValues`：确认页摘要和提交载荷读取它。
- `DeployVariableForm.vue` 的本地 `formData`：表单输入实际绑定它。

`DeployVariableForm` 只在变量定义变化时把默认值补进 `formData` 并 `emitUpdate()`；该 watcher 不监听 `formData` 内部值的变化。用户输入依赖各控件的 `@input` / `@change` 才触发 `emitUpdate()`。因此存在以下风险：

1. 默认值初始化后父组件未收到同步；
2. 自动填充或程序化修改不会触发控件事件；
3. 不同控件的事件触发时机不一致时，父组件摘要与表单显示出现分叉；
4. 提交载荷读取父组件旧值，最终部署沿用默认值。

根因需在 triage 时通过组件测试确认，不在本票中直接下结论。

## Agent Brief

**Category:** bug
**Summary:** Compose 变量输入在确认页和部署载荷中保持用户最新值

**Current behavior:**

部署向导的 Compose 变量表单维护一份内部状态，父级确认页和部署载荷读取另一份状态。变量定义异步加载后，父级补入默认值；之后在表单中修改值，父级状态没有同步更新，确认页继续显示 yml 默认值。部署载荷也读取这份旧状态，导致 `.env` 和实例配置不符合用户选择。

**Desired behavior:**

Compose 变量在表单输入、确认页摘要和部署提交之间只有一个稳定的事实来源。变量配置加载完成时，默认值进入父级状态；用户修改后，父级状态立即反映最新值。未修改的变量保留默认值，隐藏变量仍进入 `.env`，密码在确认页保持掩码。切换步骤、切换游戏或部署方式后，不得把上一组变量带到下一组或静默覆盖已修改值。

**Key interfaces:**

- `DeployVariableForm` 的 `modelValue` / `update:modelValue` 契约：`modelValue` 表示当前变量值的完整快照，任何表单变化都必须发出更新。
- `deployVariables` 与 `deployVariablesValues`：变量元信息与当前值必须分别稳定存在；确认页和 `createInstance` 载荷读取同一份当前值。
- `createInstance` 的 `configInfo`：Compose 变量继续按顶层键提交，供 `generateEnvFileContent` 读取；不得把元信息列表改成变量值对象。
- 必需变量校验：继续以表单当前值判断，未填必填值时阻止进入下一步。

### 2026-10-19 实施结果

> *This was generated by AI during triage.*

**根因**

- 部署向导和变量表单各维护一份状态，用户在表单中修改后，确认页读取的父级状态没有及时更新。
- 父组件对 `const reactive({})` 使用 `v-model`，Vue 编译时会改写绑定引用，进一步放大父子状态分叉。
- 数字变量默认值来自 yml 字符串，直接传给数字输入组件会产生类型告警。

**修复**

- 变量表单改为稳定的 `modelValue` / `update:modelValue` 快照协议：父级变化时整体同步，用户输入时整体回传。
- 部署向导使用显式更新函数，原地替换 reactive 对象内容，保证确认页、校验和提交载荷读取同一份最新值。
- 整数类型默认值在表单层规范化为 number，字符串变量和隐藏变量保持原值。
- 新增前端组件测试，覆盖异步定义加载、端口与密码修改、对外 IP 修改、完整快照和必填校验。
- 新增部署页回归测试，覆盖步骤往返、相同 Compose 部署方式下切换游戏、加载中禁止前进，以及旧配置响应晚到时不覆盖新游戏。
- 新增后端 `.env` 生成回归测试，锁定用户值优先、隐藏变量保留、必填空值拒绝。

**验证**
