# 16 — 长事务包住远端卸载，实例删除在 SQLite 下返回 500

Status: ready-for-agent
Type: bug
来源: 2026-10-20 UI E2E sdtd LinuxGSM Docker 演练腿

## 现象

删除实例 `125`（`e2e-sdtd-01`，`linuxgsm-docker`）时，DELETE 请求返回 500。
后端日志显示 `physicalDeleteById` 最终写入遇到：

```text
SQLITE_BUSY_SNAPSHOT
```

并发的主机状态同步在远端卸载期间持续写库；`deleteInstance` 的
`@Transactional` 覆盖了分钟级 SSH/Docker 卸载，使事务持有旧读快照，最终
物理删除无法提交。重试后才成功。

同一次卸载中，远端目录已被删除，随后 `docker compose down` 因
`cd: /home/haki/games/e2e-sdtd: No such file or directory` 返回
`partial_success`。这说明远端卸载和数据库记录删除被放在同一长事务内，
既扩大写锁冲突窗口，也让部分成功结果难以稳定返回。

## 复现路径

1. 在 SQLite 后端上创建 LinuxGSM Docker 实例。
2. 让主机状态同步在删除期间持续更新实例记录。
3. 调用 `DELETE /api/instances/{id}`。
4. 观察物理删除遇到 `SQLITE_BUSY_SNAPSHOT`，接口返回 500。

## 期望

- 远端卸载和插件删除钩子必须在数据库事务外执行，不得持有长读快照。
- 只有实例记录的物理删除进入短事务。
- 保持现有删除契约：远端清理失败不阻止记录删除，仍返回
  `deleted=true`、`remoteCleanupStatus`、`message` 和残留路径。
- SQLite 并发写应在短暂锁竞争时等待，不得因状态同步与删除竞争直接 500。
- 删除完成后 RCON 连接池与实例信息缓存仍按原逻辑失效。

## 验收

- [ ] 删除主流程不再有覆盖远端卸载的 `@Transactional`。
- [ ] 物理删除通过独立短事务执行，并保留“记录不存在”业务错误。
- [ ] partial-success、卸载异常和认领实例保留容器语义均有回归测试。
- [ ] SQLite 数据源启用写锁等待与 WAL，并有并发写测试。
- [ ] 定向后端测试通过；真实删除不再出现 `SQLITE_BUSY_SNAPSHOT` 500。

## Out of scope

- 修改主机状态同步周期或关闭同步。
- 改变实例删除的部分成功产品语义。
- 引入新的数据库迁移体系。
