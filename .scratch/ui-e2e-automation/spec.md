# Spec: 全量 UI 自动化测试用例集与真实主机执行

Status: ready-for-agent

> 来源：grill-with-docs 访谈共识 v3 + 接缝修订。术语遵循 `CONTEXT.md`（实例、任务、新增主机、连接测试门禁、YAML 导入、全量回归集、演练链、演练游戏、牺牲主机）。

---

## Problem Statement

平台 UI 的回归验证目前完全依赖手工执行 `docs/testing/ui-testing/` 下的清单：每次发版前人工点过十几条流程，耗时、易漏、不可重复。UI 改动后没有快速、可信的手段确认"没弄坏东西"；有真实宿主机时，也没有一套能把全部 UI 功能完整跑一遍并明确回答"哪些过、哪些没过、怎么算过"的自动化设施。

## Solution

建立一套按**页面 × 页面内功能**维度组织的 Playwright E2E 用例集，覆盖主应用全部页面与 l4d2 插件子应用全部页面功能。配套：

- **测试数据仓库**：集中收纳用例所需资产（上传用 VPK 地图、SourceMod 插件样例、YAML 导入用元数据文件等），小文件合成入库，用例只从仓库取数。
- **逐用例超时策略**：每条用例自带超时，慢操作（部署/备份/还原）放宽，整轮设全局看门狗。
- **真实主机执行**：牺牲主机可用时全量执行；不可用时主机相关用例自动 SKIP 并注明原因。
- **报告与通过判定**：每轮产出报告（总数/通过/失败/跳过 + 失败截图 + 逐用例通过标准对照）。**单条用例 = 断言全过即通过；整轮通过 = 除显式 SKIP 外全部用例通过。**

## User Stories

### 基建

1. As a 平台维护者, I want E2E 用例集按"页面 → 页面内功能"组织目录与命名, so that 我能按页面快速定位、补齐和评审用例
2. As a 平台维护者, I want 每条用例声明前置条件、操作步骤与通过标准, so that 用例失败时立刻知道违反了哪条预期
3. As a 平台维护者, I want 每条用例自带超时时间, so that 部署/备份等慢操作不拖垮整轮，卡死用例不挂死全局
4. As a 平台维护者, I want 集中的测试数据仓库收纳上传用 VPK、SourceMod 插件样例、YAML 元数据等资产, so that 用例可重复执行、不依赖临时找文件
5. As a 平台维护者, I want 一条命令完成"起后端（临时库）→ 起前端 → 跑全部用例 → 出报告 → 清理", so that 回归不依赖记忆多个手工步骤
6. As a 平台维护者, I want 牺牲主机凭据经环境变量注入、不入代码库, so that 换主机不改用例、凭据不泄露
7. As a 平台维护者, I want 宿主机不可用时主机相关用例自动 SKIP 并在报告注明, so that 无主机环境也能执行其余用例拿到部分报告
8. As a 平台维护者, I want 每轮结束自动删除本轮创建的全部游戏实例并停止相关进程, so that 不占主机内存、不留垃圾现场
9. As a 平台维护者, I want 失败用例自动留存截图与操作轨迹, so that 我能离线复盘失败原因
10. As a 平台维护者, I want 报告中逐用例对照其通过标准, so that "这轮过没过"有明确、可审计的答案

### 主应用页面

11. As a 平台维护者, I want 登录页自动化用例（成功登录、错误密码、退出登录、token 失效跳转）, so that 认证链路回归有保障
12. As a 平台维护者, I want 工作台仪表盘加载与统计渲染用例, so that 首页回归有保障
13. As a 平台维护者, I want 主机列表用例（列表渲染、新增主机走连接测试门禁、编辑、删除、连接失败错误态）, so that 主机纳管回归有保障
14. As a 平台维护者, I want 主机详情与资源监控渲染用例, so that 监控展示回归有保障
15. As a 平台维护者, I want Web 终端用例（连接成功、命令可输入）, so that 终端入口回归有保障
16. As a 平台维护者, I want 容器列表/详情可达与渲染用例, so that Docker 视图回归有保障
17. As a 平台维护者, I want 实例列表用例（渲染、筛选、状态展示）, so that 实例入口回归有保障
18. As a 平台维护者, I want 部署向导全流程用例（选游戏 → 选主机 → 选部署方式 → 端口 → 提交 → 任务创建 → 部署完成）, so that 最复杂的写链路有自动化保障
19. As a 平台维护者, I want 实例详情用例（静态数据先渲染、动态 metrics 异步加载）, so that 详情页回归有保障
20. As a 平台维护者, I want 实例操作用例（启动、停止、重启）, so that 生命周期操作回归有保障
21. As a 平台维护者, I want 备份还原用例（创建备份含进度、还原含确认、删除备份）, so that 数据安全链路回归有保障
22. As a 平台维护者, I want 游戏元数据用例（列表、YAML 导入、编辑端口）, so that 游戏目录回归有保障
23. As a 平台维护者, I want 任务中心用例（列表、详情、状态流转展示）, so that 异步任务可见性回归有保障
24. As a 平台维护者, I want 插件列表用例（显示 l4d2 已启动、进入管理跳转实例选择）, so that 插件入口回归有保障
25. As a 平台维护者, I want 系统设置用例（加载、修改保存）, so that 设置链路回归有保障

### 插件子应用（l4d2）

26. As a 平台维护者, I want Wujie 容器用例（子应用加载无 403/404、菜单切换、刷新后定位保持）, so that 微前端集成回归有保障
27. As a 平台维护者, I want l4d2 仪表盘用例（状态卡片渲染、离线提示）, so that 插件首页回归有保障
28. As a 平台维护者, I want RCON 控制台用例（执行 status 返回状态、恶意命令防注入拦截）, so that 控制台回归有保障
29. As a 平台维护者, I want 地图管理用例（列表、从测试数据仓库上传 VPK、切换地图）, so that 地图链路回归有保障
30. As a 平台维护者, I want SourceMod 插件管理用例（列表、上传样例插件）, so that 插件管理回归有保障
31. As a 平台维护者, I want 服务器配置用例（修改保存、重置默认）, so that 配置链路回归有保障
32. As a 平台维护者, I want 重启管理用例（三种重启模式展示、立即重启生效）, so that 重启链路回归有保障

### 演练链（真实主机全链路）

33. As a 平台维护者, I want 演练链按 l4d2 → dst → sdtd 串行执行（部署 → 运维 → 插件能力[仅 l4d2] → 删除实例 → 下一游戏）, so that 真实在用游戏的全链路得到完整覆盖且互不干扰
34. As a 平台维护者, I want 部署后经平台 API 验证效果（如实例文件 API 确认地图/文件写入目标目录）, so that 断言可信且测试进程无需直连 SSH
35. As a 平台维护者, I want 每条演练腿结束后删除该游戏实例, so that 主机内存不被多个游戏服占满

## Implementation Decisions

1. **工具与工程位置**：`@playwright/test` + Chromium 单浏览器；E2E 工程放主前端项目之下的 e2e 目录，复用主前端 npm scripts 生态；不引入新框架。
2. **组织维度**：目录按"页面 → 功能"两级组织；用例文件头部注释声明前置条件、步骤、通过标准，断言与通过标准一一对应。
3. **接缝**：主缝为浏览器 UI。**效果断言通道 = 平台自身 REST API（携带 JWT）**——例如地图上传后经实例文件 API 验证文件已写入实例目标目录、部署提交后经任务 API 轮询任务状态；**测试进程禁止直连 SSH**。牺牲主机的 SSH 凭据只作为"新增主机"表单的输入数据，供后端建连，测试进程自身不使用。
4. **环境契约（环境变量）**：`E2E_BASE_URL`（前端地址）、`E2E_BACKEND_URL`（后端地址，API 断言通道目标）、`E2E_ADMIN_USER`/`E2E_ADMIN_PASS`（种子管理员，用于就绪探测）、`E2E_WORKERS`（并行度）、`E2E_FAST`（受管模式跳过编译）、`E2E_TEST_HOST_ADDRESS`、`E2E_TEST_HOST_PORT`、`E2E_TEST_HOST_USERNAME`、`E2E_TEST_HOST_AUTH`（密码或私钥路径）。缺省值统一收口在环境契约模块（env），配置与 runner 从它导入。主机凭据缺失时，主机相关用例统一 SKIP 并注明 `SKIP (no test host)`。就绪标准：后端以"种子管理员真实登录成功"为准（`DatabaseInitializer` 在 Tomcat 可服务后才建核心表，端口通≠可开测），受管与附着模式一致。
5. **生命周期**：默认受管模式——runner 临时 SQLite 起后端 → 起前端 → 执行用例 → 报告 → 清理（停进程、删临时库）。另支持附着模式（attach 已运行环境，经 `E2E_BASE_URL` 指向）。每轮结束 teardown 必须经平台 API 删除本轮创建的全部实例。
6. **同步加速**：实例状态同步类用例经后端现有 instance-sync 配置项缩短同步周期（启动参数注入），不改生产代码。
7. **选择器纪律**：语义选择器（role/text，Element Plus 自带可访问性属性）优先；仅语义不可达的控件补 `data-testid`——唯一允许的生产代码改动，纯属性增量、无逻辑影响。
8. **超时策略**（逐用例声明，缺省值如下，单用例可在声明中覆盖）：

   | 类别 | 超时 |
   |------|------|
   | 普通页面交互/表单 | 30 秒 |
   | 实例启动/停止/重启 | 5 分钟 |
   | 备份/还原 | 10 分钟 |
   | 部署向导提交 → 部署完成 | 20 分钟 |
   | 上传类（VPK/插件样例，小文件） | 3 分钟 |
   | 单用例硬上限 | 25 分钟 |

   另设整轮全局看门狗，超时即中止并产出部分报告。
9. **演练链**：演练游戏 l4d2 → dst → sdtd 串行；每条腿 = 部署 → 运维能力（启停/重启/备份/还原）→ 插件能力（仅 l4d2 有插件）→ 删除实例清理现场。腿间与轮末都必须无残留实例。
10. **报告**：Playwright HTML 报告 + 控制台摘要（总数/通过/失败/跳过）；失败附截图与 trace；SKIP 附原因。报告即"整轮是否通过"的判定依据。
11. **测试数据仓库**：独立资产目录随用例工程入库。内容：最小可用 VPK 地图样例、SourceMod 插件样例文件、YAML 导入用游戏元数据文件、可修改的配置样例。小文件合成生成后提交，禁止用例运行时临时从外网下载资产。

## Testing Decisions

- **只测外部行为**：断言对象限于用户可见结果（页面渲染、提示、跳转）与平台可观测状态（任务状态、实例状态、实例文件 API 可见产物）。不断言内部实现、不直查数据库。
- **好用例标准**：用 Playwright auto-wait / `expect.poll` 轮询等待，禁止固定 sleep；每条用例数据自备、现场自清，可独立重跑。
- **覆盖模块**：主应用 15 个页面全部功能 + l4d2 插件子应用全部页面（仪表盘/RCON 控制台/地图管理/SourceMod 插件管理/服务器配置/重启管理）+ 主应用备份还原 + 演练链。
- **断言深度取舍**：Web 终端只断言"连接成功 + 命令可输入"，不对 xterm canvas 做输出文本断言（脆弱）。
- **Prior art**：用例蓝本 = `docs/testing/ui-testing/07-e2e-checklist.md`（以它为底本拆成自动化用例，清单中"尽量通过/可选"项逐条标明处理方式）；工程约定参考主前端现有 Vitest 测试的组织方式。

## Out of Scope

- **CI 门禁/冒烟集进 CI**：降级为后续可选阶段（"冒烟集"术语已录入 `CONTEXT.md`，本轮不实现）。
- **组件/单元测试补齐**：现有约 27 个 Vitest 组件测试维持现状。
- **浏览器矩阵**：仅 Chromium；Edge/Firefox/Safari 不在本轮。
- **性能门槛**：清单中 E2E-300 系列性能项只记录数值，不作为通过门槛。
- **移动端/响应式验证**。
- **SteamCMD 大文件下载优化**：接受演练耗时（单轮 30 分钟以上）。
- **ADR 记录**：用户已决定不为测试双轨制写 ADR。

## Further Notes

- 牺牲主机授权边界：**专用测试 Linux 主机、全权限**（自动化可部署/启停/备份还原/删除），与开发/生产主机严格隔离。首次使用需人工把凭据写入环境变量。
- 演练游戏下载量：l4d2/dst/sdtd 均为数 GB 级（SteamCMD/LinuxGSM 源），全量一轮预计 30 分钟以上，用户已明确接受。
- 后端拉起方式复用现有 `start-all.sh --db` 独立库能力；前端用构建产物或 dev server 由实现票决定，规格不锁定。
- 实施顺序建议：基建（工程/数据仓库/环境契约/报告）→ 主应用只读与表单类用例 → 主应用写操作与实例生命周期 → 插件子应用 → 演练链。
