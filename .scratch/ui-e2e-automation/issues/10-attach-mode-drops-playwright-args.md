# 10 — runner 附着模式未透传 Playwright 位置参数

Status: done
Type: bug
来源: 2026-10-20 定向 E2E 执行（dst/sdtd 演练腿）

## 现象

以下命令本意是只运行 `drill-legs.spec.js`：

```powershell
npm run e2e -- --attach e2e/main-app/instance/drill-legs.spec.js --reporter=list
```

runner 正确进入附着模式，但实际执行了 80 个 Playwright 用例。原因是
`runner.mjs` 仅从字面量 `--` 之后提取 Playwright 参数：

```js
const passthroughIndex = process.argv.indexOf("--")
const PLAYWRIGHT_ARGS =
  passthroughIndex === -1 ? [] : process.argv.slice(passthroughIndex + 1)
```

npm 会在启动脚本前消费 `--`，因此 runner 收到的 `process.argv` 中没有该分隔符，
后续位置路径和 `--reporter=list` 被静默丢弃。

## 期望

- `npm run e2e -- --attach <spec> --reporter=list` 只执行指定 spec。
- runner 自身参数（`--attach` / `--round`）与 Playwright 参数可靠分离，不依赖 npm 是否保留 `--`。
- 未传位置参数时仍保持“运行全部用例”的既有行为。
- 增加参数解析回归测试，覆盖 npm 调用、直接 node 调用、`--attach`、`--round` 和 Playwright reporter 组合。

## 验收

- [ ] 附着模式定向命令只运行指定 spec，不再隐式执行全套用例。
- [ ] `--attach` 与 `--round` 不会传给 Playwright 并被误判为未知参数。
- [ ] 无位置参数时仍运行默认测试集合。
- [ ] runner 参数解析有自动化测试覆盖。

## Out of scope

- 修改单个 Playwright 用例的业务断言。
