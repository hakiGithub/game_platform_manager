# 01: 热部署先卸载插件，后校验构建产物，且 Jar 命名与 Maven 产物不一致

Status: done
Type: bug
来源: 2026-10-20 跟进 dnf-tw 问题 05 后热部署 L4D2 插件

## 现象

执行 Maven 打包后，插件构建实际生成：

```text
backend/plugin-l4d2/plugin-l4d2-core/target/plugin-l4d2-core-1.0.0-SNAPSHOT.jar
```

但热部署脚本默认查找：

```text
backend/plugin-l4d2/plugin-l4d2-core/target/plugin-l4d2-core-1.0.0.jar
```

当使用 `--skip-build`，或外部直接构建后再部署时，脚本可能已经完成 PF4J
`stop` 与 `DELETE unload`，随后在复制阶段才发现源 Jar 不存在。此时插件处于
`ABSENT`，而脚本只打印复制失败，后端实际没有可用插件。

2026-10-20 已真实复现：后端 `8080` 与前端 `3002` 均正常运行，`plugin-l4d2`
先被卸载，复制失败；随后手工加载既有部署 Jar 才恢复为 `STARTED`。

## 根因

1. 插件版本来自父 POM 的 `1.0.0-SNAPSHOT`，Maven 产物因此带 `-SNAPSHOT`；
      脚本却硬编码部署文件名 `plugin-l4d2-core-1.0.0.jar`，并把同一名称用于
      构建源文件查找。
2. 构建产物的存在性校验发生在卸载之前，但默认路径不正确，导致校验被绕过；
      当使用 `--jar` 或某些入口直接调用后续步骤时，也没有在卸载前再次确认
      最终可部署文件。
3. 脚本没有在卸载后复制失败时自动回滚旧 Jar 并恢复插件。

`backend/scripts/build-and-deploy.ps1` 同样硬编码
`target\plugin-l4d2-core-1.0.0.jar`，与实际 Maven 产物不一致。

## 期望行为

- 部署脚本从 Maven 的最终产物解析 Jar，不依赖硬编码版本后缀；至少支持
  `plugin-l4d2-core-1.0.0.jar` 和 `plugin-l4d2-core-1.0.0-SNAPSHOT.jar`。
- 在调用任何插件卸载接口之前，确认源 Jar 存在、是普通文件且非空。
- 将候选 Jar 复制到临时文件，并校验大小/可读性后，才允许卸载旧插件。
- 卸载后替换、加载或启动任一步失败时，自动恢复旧 Jar 并重新加载旧插件；
  最终回报原错误以及回滚是否成功。
- 同一套产物发现与校验逻辑由 Bash 热部署脚本和 PowerShell 部署脚本共用，
  避免再次出现两套命名规则。
- 回归测试覆盖产物名解析、源 Jar 不存在时不调用卸载、替换失败回滚，
  以及正常热部署后状态为 `STARTED`。

## 验收

- [x] 使用默认 Maven 版本构建时，脚本能找到 `-SNAPSHOT` Jar。
- [x] 源 Jar 不存在或为空时，PF4J 插件保持原状态，不发送 `stop`/`unload`。
- [x] 源 Jar 在卸载前被验证；复制/加载失败后旧插件自动恢复并最终 `STARTED`。
- [x] `scripts/deploy-plugin.sh` 与 `backend/scripts/build-and-deploy.ps1`
      使用同一产物解析规则或在测试中锁定一致的候选规则。
- [x] 测试可在无 Bash 的 Windows PowerShell 环境运行。
- [x] 热部署结束后重新查询 PF4J，`plugin-l4d2` 为 `STARTED`，后端仍健康。

- 自动清理用户工作区中已有的插件 Jar。
