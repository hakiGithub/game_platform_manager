# 02: 插件存在 config_files 元数据时仍混入按名称推导的候选文件

Status: done
Type: bug
来源: 配置编辑器多文件实现复核（2026-10-20）

## 现象

插件 meta（`plugin.yaml`）声明多个 `config_files` 时，配置接口还会追加按插件显示名推导出的 cfg 候选。真实插件名通常不是 cfg 文件名，因此响应会同时包含：

- meta 声明且实际存在的 cfg 文件；
- 以插件显示名推导、实际不存在的若干 `MISSING` 文件。

这会让同一插件在配置弹窗中出现无关的缺失文件分组。若按名称推导的候选恰好存在，还可能把未声明的文件当成该插件配置展示。

## 复现路径

1. 为实例中的插件写入包含 `config_files` 的 `plugin.yaml`。
2. 调用 `GET /api/plugin/l4d2/plugin-config/get`。
3. 检查响应中的 `configFiles`。

## 期望

- meta 存在且声明了至少一个有效 `config_files` 时，配置文件集合只使用声明项，不再追加按插件名推导的候选。
- meta 不存在、未声明 `config_files` 或声明项为空时，继续使用按插件名推导的兼容候选。
- 同名但位于不同目录的声明文件必须分别保留，不按 basename 合并。
- 配置更新与恢复默认值只接受响应中实际可选的声明文件。

## 验收

- [x] 有 meta 声明的插件不会返回未声明的名称推导候选。
- [x] 无 meta 或空 `config_files` 的旧插件仍能读取按名称推导的 cfg。
- [x] 多个声明文件全部出现在响应中，即使其中一个不存在也保留该声明项并显示清晰状态。
- [x] 保存与恢复默认值仍按 `fileId`/完整路径精确匹配。
- [x] 回归测试覆盖“声明三项但名称推导不存在”“无 meta 回退”“同名不同目录”。

### 2026-10-20 Triage 结论

**分类：** bug
**状态：** ready-for-agent

已确认 `SourceModCfgService.getCandidatePaths()` 在读取到非空 `config_files` 后仍无条件追加 `getNameBasedCandidates()`。真实插件显示名与 cfg 文件名不同，因此多文件配置响应会混入无关 `MISSING` 项。

修复必须保留插件库副本的读取能力，但不能把副本路径成对暴露成独立文件；同目录同名声明去重后按 basename 唯一匹配，避免 `fileId` 与保存目标错位。

### 2026-10-20 实施结果

有非空 meta 声明时只使用声明文件；无 meta 或声明为空时回退名称推导。声明目标绑定稳定 `fileId`，同名不同目录分别保留；仅提供 basename 且命中多个声明时明确拒绝，要求使用完整路径。
