# 03: SourceMod 的 Minimum/Maximum 元数据被遗漏并污染配置描述

Status: done
Type: bug
来源: 配置编辑器真实插件复核（2026-10-20）

## 现象

实例 97 的“自选-多特感插件(v1.3.7)(Tordecybombo, breezy)”配置页中，`specialspawner.cfg` 的范围列全部显示 `- ~ -`，同时部分说明文字显示为：

```text
Minimum: "0.000000" Maximum: "32.000000"
```

SourceMod cfg 中实际使用 `Minimum:` / `Maximum:` 标注范围，而当前解析器只识别 `Min:` / `Max:`，并且只从描述中移除后者。结果是范围字段没有写入，原始元数据又泄漏到用户可读说明中。

## 复现路径

1. 打开实例 97 的 L4D2 插件配置页。
2. 选择“自选-多特感插件(v1.3.7)(Tordecybombo, breezy)”。
3. 展开 `specialspawner.cfg`。
4. 检查配置项的范围列和说明列。

## 期望

- 解析器同时识别 `Min:` / `Minimum:` 与 `Max:` / `Maximum:`，大小写不敏感。
- 数字允许使用双引号或单引号包裹，例如 `Minimum: "0.000000"`。
- 识别到的值正确写入 `ConfigItem.min` / `ConfigItem.max`，页面展示原始精度允许的正常数值。
- `Minimum:` / `Maximum:` 及其值从 `ConfigItem.description` 中移除，不得在说明列泄漏。
- 同行注释和配置项上方注释块使用相同行为。
- 原有 `Min:` / `Max:` 格式保持兼容。
