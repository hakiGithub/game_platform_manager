# 01: deploy-plugin.sh 将运行中的后端误判为离线

Status: done
Type: bug
来源: 用户反馈（2026-10-20）

## 现象

`scripts/deploy-plugin.sh` 在热部署 `plugin-l4d2` 时输出：

```text
后端未运行：JAR 已放入 plugins/，下次 start-all.sh 启动时自动加载
```

但后端实际正在 `8080` 端口运行，PF4J 接口可正常登录和访问。

## 根因

脚本通过以下 GET 请求探测后端：

```text
GET /api/auth/login
```

该端点只接受 `POST`，运行中的后端返回 HTTP 405。脚本仅将 HTTP 000
视为离线，却把其他非 200 响应的探测结果传入后续状态判断，最终进入离线分支。
JAR 被覆盖但未执行 PF4J 卸载/加载，运行中的插件仍使用旧代码。

## 期望

- 后端运行且返回任意 HTTP 响应（包括 405）时，不得进入“后端未运行”分支。
- 只有连接失败或超时才进入离线落盘分支。
- 修复后热部署能完成卸载、覆盖、加载，并确保插件状态为 `STARTED`。

## 验收

- [x] `deploy-plugin.sh` 对运行中的后端不再误报离线。
- [x] 脚本以明确、可验证的 HTTP 探活方式判断服务可达性。
- [x] 后端在线时执行完整 PF4J 热部署流程。
- [x] 后端离线时仍保留 JAR 落盘行为。
- [x] 用当前 `plugin-l4d2` 实际部署验证，后端不重启且插件加载新代码。

### 2026-10-20 实施结果

**根因**

- 健康探测把任何非 200 响应都当成服务不可用；登录接口只接受 POST，因此在线后端返回 405 后被误判为离线。
- PowerShell 下实际调用的是 WSL Bash，WSL 的 `localhost` 无法访问 Windows 宿主机上监听的 8080 端口。
- WSL 环境只有 `python3`，脚本原先硬编码了 `python`。

**修复**

- 仅将 HTTP `000`（连接失败或超时）视为离线；任意 HTTP 响应都继续执行热部署。
- WSL 自动解析默认路由的 Windows 主机地址，并支持用 `GPM_SERVER_HOST` 显式覆盖。
- 自动选择 `python3` 或 `python`。
- 新增 PowerShell 回归测试，锁定 405 不再进入离线分支。
