# 03: 地图详情读取解析到错误的 VPK 文件

Status: resolved
Type: bug
来源: Issue 01 复核（L4D2 实例 ID 97，2026-10-20）

## 现象

地图列表能正确返回 `red_square.vpk` 的战役信息，但按同一 VPK 请求 mission 详情时，响应中的 `vpkName` 变成了另一个文件，且 `title`、`chapters` 为空：

```http
GET /api/plugin/l4d2/maps/red_square.vpk/mission?instanceId=97
```

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "vpkName": "l4d2_mission_6429457440640959025.vpk",
    "title": null,
    "chapters": null
  }
}
```

同一时刻地图列表中的 `red_square.vpk` 返回 `title: Red Square Campaign`，包含 5 个章节。说明列表读取和 mission 详情读取没有解析到同一个物理文件，或详情接口对文件名使用了错误的候选规则。

## 复现步骤

1. 打开 L4D2 实例 97 的地图管理。
2. 调用 `GET /api/plugin/l4d2/maps/list?instanceId=97`，确认存在 `red_square.vpk` 且 `recognitionStatus: OK`。
3. 对该 `vpkName` 调用 `GET /api/plugin/l4d2/maps/red_square.vpk/mission?instanceId=97`。
4. 观察返回的 `vpkName`、`title` 和 `chapters` 与列表不一致。

## 期望

- 按列表返回的 `vpkName` 请求 mission 详情时，必须解析同一个物理 VPK。
- 详情响应中的 `vpkName` 与请求参数一致；无法读取时返回明确错误，不得以另一个文件的空详情冒充成功。
- 列表和详情对路径、文件名、大小写转换、URL 解码、容器路径与宿主机路径使用同一解析契约。
- 详情读取失败不能破坏列表或修改其他地图的识别缓存。
- 同一 VPK 的标题、章节和开图命令在列表与详情之间保持一致。

## Agent Brief

**Category:** bug
**Summary:** mission 详情必须读取请求指定的同一个 VPK，并返回一致的标题与章节

**Current behavior:**

地图列表能返回 `red_square.vpk` 的完整章节，但同一 `vpkName` 的 mission 详情返回另一个文件名，且标题和章节为空。接口仍以成功响应包装该结果，调用方无法判断文件是否读取失败，也无法信任详情内容。

**Desired behavior:**

mission 详情只读取请求指定的 VPK，响应中的文件标识必须与请求一致。成功时标题与章节应与列表的同一地图一致；文件不存在、不可读或解析失败时，返回明确业务错误，不得返回另一个文件的空详情。

文件名处理需覆盖 URL 解码、空格、下划线、数字后缀和大小写，但不允许通过目录扫描后“取第一个相似文件”来弥补路径解析错误。列表和详情应共享同一个稳定文件定位契约。

**Key interfaces:**

- `MapController` 的 `/maps/{mapName}/mission`：目标 VPK 名必须原样绑定并校验，不得使用隐式候选或旧路径规则。
- `MapService` 的 mission 读取方法：应返回请求文件对应的 `MissionInfoVO`，不能复用列表的第一个识别结果。
- `MissionInfoVO`：`vpkName` 必须等于请求目标；无标题或章节时不得伪装为成功空详情。
- 地图文件路径解析：列表和详情必须共享同一 addons 根目录与容器路径解析规则。

**Acceptance criteria:**

- [ ] 请求 `red_square.vpk` 时，mission 响应中的 `vpkName` 严格为 `red_square.vpk`。
- [ ] 成功响应中的标题和章节与同一时刻列表条目一致。
- [ ] 请求不存在的文件名返回业务失败，不返回目录中另一个 VPK 的详情。
- [ ] 空格、下划线、数字后缀、大小写和 URL 编码文件名均能正确往返。
- [ ] 读取 mission 不修改地图列表顺序、识别状态或其他 VPK 缓存。
- [ ] 服务层或控制器测试覆盖“目录有多个 VPK，仅请求其中一个”和“请求不存在文件”两条路径。
