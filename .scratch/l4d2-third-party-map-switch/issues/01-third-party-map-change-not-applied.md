# 01: L4D2 切换第三方地图后未生效

Status: resolved
Type: bug
来源: 用户反馈（2026-10-19）

## 现象

在 L4D2 实例中请求切换第三方地图 `c1918_red_square_c1` 后，`/rcon/status` 没有返回或保持为该目标地图，服务器仍停留在原地图。

用户提供的顺序：

1. 调用 `POST /api/plugin/l4d2/rcon/change-map`，请求体包含 `{"instanceId":97,"mapName":"c1918_red_square_c1"}`。
2. 随后调用 `POST /api/plugin/l4d2/rcon/status`，请求体包含 `{"instanceId":97}`。
3. `status` 返回的地图不是替换后的三方地图 `c1918_red_square_c1`。

复现入口：

- L4D2 地图管理页切换第三方地图。
- 或直接调用上述两个接口，以状态接口返回的 `map` 为最终判定。

## 期望

- 对已安装且服务器可识别的第三方地图，`change-map` 成功后，`status` 在合理等待时间内返回 `c1918_red_square_c1`。
- 若服务器拒绝或无法加载该地图，接口不能只返回成功；需要给出可定位的失败结果或明确状态。
- 原有地图管理能力（列表展示、选择地图、触发切换）继续可用。

## 已核对的现状

- 前端 `changeMap` 调用 `/rcon/change-map`。
- 后端接口目前只执行 `changelevel <mapName>`，未把 RCON 输出或换图结果作为响应返回。
- 仓库已有相关但不完全相同的问题：Docker addons 地图列表不可见（已记录、状态为 done）以及换图终态未被 E2E 强断言。本 issue 聚焦“接口返回/状态显示未切到指定三方地图”。

## Agent Brief

**Category:** bug
**Summary:** 换图接口必须解析 RCON 结果并返回可验证的成功或失败，不再把服务器拒绝报告为成功

**Current behavior:**

`change-map` 执行 `changelevel <mapName>` 后直接返回成功，忽略 RCON 输出。目标地图不存在、服务器拒绝换图或命令未生效时，调用方仍收到 HTTP 200 业务成功，前端无法知道换图是否发生。`/rcon/execute` 也仅区分传输异常，不识别失败回显。

**Desired behavior:**

换图调用返回结构化结果，至少包含是否被服务器接受、原始 RCON 输出和可读错误。服务器对 `changelevel` 返回未知地图、加载失败或 `changelevel failed` 时，接口必须返回业务失败，不得返回空成功。若只确认“命令已发送”而尚未确认地图已切换，结果状态必须区别于“已切换”；调用方可以轮询状态接口确认终态，但必须有合理上限并返回最后观测到的地图。

失败回显识别应覆盖 L4D2 的典型输出，例如 `No such map`、`changelevel failed`、`not found`，同时避免因为正常文本偶然包含通用单词而误判成功。保留现有 RCON 传输异常语义。

**Key interfaces:**

- `L4D2RconService.changeMap()`：当前返回 `void` 并丢弃输出；应返回可表达接受/拒绝及原始输出的结果。
- `RconController.changeMap()`：当前返回 `Result<Void>`；应返回前端可区分成功、失败和待确认的结构化结果。
- 前端 `rconApi.changeMap()` 及地图选择器、地图中心、下载完成后的开图调用：需要处理非成功结果，不得先提示成功再刷新状态。
- 现有失败检测工具：应扩展地图加载错误标记，避免复制第三套关键词表。

**Acceptance criteria:**

- [ ] 当 RCON 回显包含 `No such map` 或 `changelevel failed` 时，`change-map` 返回业务失败，并携带目标地图名与原始回显。
- [ ] 当 RCON 连接失败、认证失败或实例离线时，接口返回明确失败，不返回空成功。
- [ ] 正常 `changelevel` 不会仅因普通状态文本而被误判为失败。
- [ ] 前端在接口失败时显示错误，不显示“切换成功”，且不把本地选中状态当成服务器已切换。
- [ ] 如果实现等待终态，使用有上限的超时；超时返回最后观测地图并明确标记未确认，不无限阻塞请求。
- [ ] `/rcon/execute` 至少不在输出明显表示命令失败时仍标记 `success: true`，或明确区分“传输成功”与“命令执行失败”两个字段。
- [ ] 单元测试覆盖成功、地图不存在、换图失败、RCON 不可达和等待超时；至少一条前端测试覆盖失败提示与状态回滚。

**Out of scope:**

- 修复 VPK 被识别为 `OK` 但服务器运行时不可见的问题。
- 自动安装缺失地图或自动重启服务器。
- 改变 `changelevel` 以外的地图切换机制，除非现有游戏能力无法获得可验证结果。
- 把用户提供的 token、cookie 或脱敏请求头写入测试夹具或日志。
