# 04: mission 详情失败被包装成通用 500

Status: resolved
Type: bug
来源: Issue 03 修复后的真实接口验证（L4D2 实例 97，2026-10-20）

## 现象

请求：

```http
GET /api/plugin/l4d2/maps/red_square.vpk/mission?instanceId=97
```

返回：

```json
{
  "code": 500,
  "message": "系统异常,请联系管理员",
  "data": null
}
```

服务层已经能拒绝空战役信息，但插件业务异常没有被转换为可读的 `Result.fail`，调用方无法知道是文件不存在、VPK 解析失败、主机工具失败还是实例不可用。

## 期望

- mission 详情的业务失败和文件失败返回明确的业务码与消息。
- 消息包含目标 VPK 名，不泄露 SSH 密码、Rcon 密码或环境文件内容。
- 不存在的 VPK 不再返回另一个文件的空详情，也不退化成通用“系统异常”。
- 列表读取与详情读取的失败语义可区分。

## 验收

- [x] 不存在的 VPK 返回非 200 业务码，消息包含该文件名。
- [x] 空 mission 或不可解析 VPK 返回文件类错误，不返回 `data` 空成功。
- [x] 容器工具不可用、实例不存在等异常返回各自可读消息。
- [x] `MapController` 或统一插件异常处理有回归测试。
- [x] 真实实例 97 复测错误响应可定位。

### 2026-10-20 实施与真实验证

**实现**

- `MapController.getMission()` 捕获 `L4D2PluginException` 并转换为
  `BusinessException`，保留地图文件名和具体失败消息。
- `MapService.getMission()` 对空标题、空章节、目标文件不存在和主机工具失败
  使用插件文件/业务异常，不再返回空成功数据。
- 新增 controller 回归测试，锁定业务失败和文件失败的消息传播。

**验证**

- 后端定向测试 34 个通过。
- 最新插件 JAR 已热部署，插件状态 `STARTED`，运行包与构建包 SHA-256 一致。
- 真实实例 97 请求不存在 VPK 返回 `code:400` 和
  `地图不存在: does-not-exist.vpk`。
- `red_square.vpk` 请求已从通用 500 变为 `code:400`，消息包含
  `解析 mission 失败`、目标 VPK 和主机工具错误，满足错误可定位要求。
- 本次复测先发现宿主 SDK 热部署签名不匹配（issue 05），重启主应用后已消除；
  剩余 VPK 分析运行时失败由 issue 06 跟踪。
