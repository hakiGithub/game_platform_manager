# 02: 第三方地图识别为 OK 但游戏运行时无法加载

Status: needs-info
Type: bug
来源: Issue 01 真实环境复现（L4D2 实例 ID 97，2026-10-19）

## 现象

地图管理接口把 `red_square.vpk` 识别为可用，返回了战役标题、章节和开图命令，但游戏服务器运行时看不到该地图，也不能通过 `changelevel` 加载。

同一实例的实测结果：

1. 地图列表返回：

   ```text
   title: Red Square Campaign
   vpkName: red_square.vpk
   recognitionStatus: OK
   chapter: c1918_red_square_c1
   launchCommands: ["map c1918_red_square_c1"]
   ```

2. 执行 RCON `maps *` 后，输出只包含官方地图，没有 `c1918_red_square_c1`。
3. 执行 RCON `changelevel c1918_red_square_c1` 后，原始回显为：

   ```text
   CModelLoader::Map_IsValid:  No such map 'maps/c1918_red_square_c1.bsp'
   changelevel failed: c1918_red_square_c1 not found
   ```

这说明“VPK 被平台识别”和“VPK 已挂载进游戏进程且包含可加载 BSP”是两个不同条件；当前前者为真时，界面会误导用户认为地图可以直接切换。

## 复现环境

- 实例：L4D2 实例 ID 97
- 目标地图：`c1918_red_square_c1`
- VPK：`red_square.vpk`
- 初始运行地图：`c2m1_highway`
- 复现期间地图状态始终未离开 `c2m1_highway`

## 期望

- 地图列表能区分“文件存在且可解析”与“服务器运行时已注册该 BSP”。
- 只有服务器实际可见、能够加载的地图才显示为可直接切换的 `OK` 状态。
- 文件存在但运行时不可见时，状态和错误信息应明确指出原因与可采取的恢复动作，例如重新挂载或重启服务器、检查 VPK 内容、检查容器卷映射。
- 地图切换入口应基于服务器的运行时地图集合过滤或禁选不可加载的战役，避免把 RCON 必然失败的章节展示成可用选项。

## 验收

- [ ] 对一个真实缺少 BSP、未被服务器挂载或卷路径不一致的 VPK，地图列表不再显示为可直接切换的 `OK`。
- [ ] 对服务器已挂载且 `maps *` 可见的三方地图，识别状态和实际可切换结果一致。
- [ ] 不可加载场景显示可定位的原因，包含 VPK 名、目标地图名和至少一项恢复建议。
- [ ] 地图选择器不会把运行时不可见的章节作为可成功切换的选项。
- [ ] 修正文件路径、重新挂载或重启后重新识别，状态能从不可用恢复为可用。
- [ ] 覆盖至少一条回归测试：VPK 存在且可解析，但服务器运行时地图集合缺少目标 BSP 时不得返回 `OK`。

## Out of scope

- 修复 RCON 换图接口吞掉失败回显的问题；该问题由同目录 Issue 01 跟踪。
- 自动修改用户的 VPK 内容或替用户生成地图素材。
- 改变游戏服务器镜像本身的地图扫描策略，除非验证证明平台无法在现有挂载机制下获得正确运行时状态。
