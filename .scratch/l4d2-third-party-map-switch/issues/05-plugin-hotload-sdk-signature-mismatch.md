# 05: 插件热部署后调用宿主 SDK 新方法触发 NoSuchMethodError

Status: resolved
Type: bug
来源: Issue 04 热部署后真实接口复测（L4D2 实例 97，2026-10-20）

## 现象

插件热部署成功且状态为 `STARTED`，但调用 mission 详情时返回通用 500：

```json
{"code":500,"message":"系统异常,请联系管理员","data":null}
```

后端日志中的真实异常：

```text
java.lang.NoSuchMethodError:
'com.gameplatform.plugin.service.VpkAnalyzeResult
com.gameplatform.plugin.service.HostToolingService.inspectVpk(java.lang.Long, java.lang.String)'
```

调用点：

```text
MapService.getMission(MapService.java:439)
```

## 根因

- 新插件 JAR 是按最新 `game-platform-plugin` SDK 源码编译的，调用了
  `HostToolingService.inspectVpk(Long, String)`。
- 运行中的主应用 JVM 仍从启动时已加载的 `game-platform-plugin` JAR 解析该接口，
  其中还没有 `inspectVpk` 方法。
- `deploy-plugin.sh`/手工热部署只替换插件 JAR，不会刷新主应用 classpath 中的
  provided SDK 依赖，因此插件显示 `STARTED` 也不能证明宿主 API 契约与插件一致。

## 期望

- 插件发布或热部署前能发现宿主 SDK 方法缺失，而不是等业务请求触发
  `NoSuchMethodError`。
- 主应用与插件使用兼容的 SDK 版本；新增宿主服务接口时明确要求重启主应用，
  或提供可验证的版本握手。
- 热部署验证至少覆盖一次插件对新宿主 API 的调用，避免只检查状态为 `STARTED`。
- 错误响应仍保持可定位；运行时链接错误应记录为部署/兼容性故障，不应伪装成
  地图文件或 VPK 解析失败。
