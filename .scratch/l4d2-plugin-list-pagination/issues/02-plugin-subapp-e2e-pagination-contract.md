# 02: 插件子应用 E2E helper 未适配插件列表分页响应

Status: done
Type: bug
来源: 2026-10-20 附着模式 E2E 真实运行（实例 97）

## 现象

`frontend/e2e/plugins/l4d2/plugin-subapp.spec.js` 的 `pluginRow()` 仍把
`GET /api/plugin/l4d2/plugins/list` 的 `data` 当作数组：

```js
return (list.body?.data ?? []).find((row) => row.name === name) ?? null
```

插件列表分页改造后，接口返回 `PageResult`，实际记录位于
`data.records`。因此 `find` 不存在，`SourceMod 插件禁用/启用切换并恢复原状态`
用例直接抛出：

```text
TypeError: ((intermediate value) ?? []).find is not a function
```

该失败会中断同一 serial 文件中的后续用例，导致分页改造后的 E2E 无法完成整轮回归。

## 复现路径

1. 平台前后端运行中，L4D2 实例 97 已有 `e2e-sample-plugin`。
2. 运行 `plugin-subapp.spec.js` 的 `SourceMod 插件禁用/启用切换并恢复原状态`。
3. `pluginRow()` 解析分页响应时把对象交给 `.find()`。

## 期望

- E2E API helper 按当前分页契约读取 `data.records`，不再假设 `data` 是数组。
- helper 显式请求足够大的页，或在分页结果中按名称查询，确保目标插件不因默认页大小而丢失。
- 禁用/启用切换用例可通过 API 回读状态，并继续在 UI 刷新后核对目标行。
- 增加契约测试或断言，避免未来接口响应结构变化再次以 `TypeError` 形式中断 serial 用例。
