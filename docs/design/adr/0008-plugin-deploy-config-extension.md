# ADR-0008：插件部署方式配置扩展

- 状态：已接受（2026-08-16）
- 关联：ADR-0002（范围隔离）、ADR-0006（补丁安装决策树）

## 背景

游戏部署方式的配置（部署类型选项、compose 模板、变量、镜像等）目前只能由
主应用 `games/*.yml` 游戏元数据维护。游戏插件的部署方式演进（镜像变更、
模板调整）必须改主应用 yml，与 ADR-0002 的"插件业务配置插件自负"原则相悖。

## 决策

插件通过新扩展点声明部署方式配置模板，主应用**读取时合并**：

1. **扩展点**：`GameEnhancementExtension.getDeployConfigs()`（默认空列表）
   返回 `List<DeployConfigDeclaration>`（record：`deployType` + `config` 配置节）。
   `config` 与主应用 yml `deployConfig` 的同名节完全同构，合并零转换。

2. **合并时机**：读取时合并（`getGameList` / `getDeployConfig` 查询时），
   不落库。插件热部署后立即生效，无需重扫游戏元数据。

3. **选项合并**：部署向导选项 = yml `supportedDeployTypes` ∪ 插件声明类型
   （插件声明即选项）。仅合并主应用支持的部署类型 code
   （linuxgsm / docker / docker-compose / linuxgsm-docker），
   未知 code 忽略并告警。

4. **配置覆盖**：同一部署类型下，插件声明**整节替换**主应用 yml 同名节，
   插件优先。不做字段级深合并（嵌套 Map 合并语义复杂易错）。

5. **执行归属**：执行仍走主应用部署适配器（DeployAdapter 体系），
   插件仅提供配置。全新部署类型（超出 4 种）不在本次范围。

## 理由

- 部署配置随插件版本演进，插件声明是"该游戏当前正确的部署配置"的权威表达
- 读取时合并避免扫描器与插件加载时序耦合，热部署即生效
- 整节替换语义清晰，插件节自洽完整
- 执行体系稳定，本次不动适配器，风险可控

## 后果

- 新游戏插件可直接声明部署配置，无需主应用维护 yml 部署节
- 主应用 yml 部署节退化为"无插件时的基线"
- 后续如需全新部署类型（超出 4 种），需将 DeployAdapter SPI 化并扩展
  执行侧（本次明确不做）
