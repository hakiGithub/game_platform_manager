# ADR-0028: 地图中心增量爬取水位线早停

- 状态：Accepted
- 日期：2026-09-17
- 关联：[ADR-0027](0027-l4d2-map-recognition-launch-commands.md)（同插件前序工作）、爬取任务（ADR-0018 同期任务化基础设施）

## Context

地图中心爬虫（ORANGE 源）的 INCREMENTAL 模式只在**详情阶段**跳过未变化条目，**列表阶段永远全量翻页**——站点约 805 张图、每页 8 条，每次增量仍发出近百次列表请求。站点列表页实测严格按"更新时间"倒序排列（2026-09-17 实测第 1/2 页日期单调不增），因此翻页可以在"整页都是旧条目"时提前停止。

顺带发现语义分叉：`MapSpec.sourceUpdateDate` 优先存详情侧日期，而增量跳过条件拿它与**列表**"更新时间"比较，部分记录可能永不命中跳过。

## Decision

1. **水位线从库内派生**：爬取启动时计算 `watermark = max(条目.listUpdateDate，缺失回退 sourceUpdateDate) − 7 天`。不建独立水位线存储（无表、无丢失风险）；−7 天为站点乱序与时钟偏差的安全冗余。

2. **增量早停**：INCREMENTAL 逐页抓取，当**一整页所有条目**的更新时间都 ≤ 水位线时停止后续翻页（当前页条目仍走逐条增量判断）；至少翻满 2 页才允许早停。乱序保护：若某页出现比已见最大日期更新的条目（排序假设破坏），放弃早停、继续全量翻页并记日志。FULL 模式行为不变。

3. **列表更新时间独立存储**：`MapSpec` 新增 `listUpdateDate`（列表页"更新时间"，专用于增量比较与水位线），`sourceUpdateDate` 保持展示语义不变。存量记录首次增量走回退比较：`listUpdateDate` 缺失时沿用 `sourceUpdateDate == 列表更新时间` 判断，命中即跳过并**免详情回填** `listUpdateDate`；未命中的记录抓一次详情自然补齐（一次性成本）。

4. **触发节奏**：定时增量改为每日凌晨（早停后增量成本 ≈ 1-3 页请求）；每周日额外一次全量对账。沿用现有配置开关，手动"全量爬取"按钮保留为人工兜底。

## Consequences

- 增量爬取请求量从「全页列表 + 未变化条目 0 详情」降为「1-3 页列表 + 少量详情」。
- 站点若改为非时间排序，乱序保护会使增量自动退化为全量行为（正确性优先，成本回退）。
- `MapSpec.listUpdateDate` 为新增字段，存量记录按回退策略渐进补齐，无需迁移脚本。

## Alternatives

- **上次爬取时刻做水位线**：被否（用户裁决）——按库内更新日期派生，无独立状态可丢失。
- **自动升格全量对账**：被否——手动全量保留即可，避免"偶尔全量"不可预期。
- **详情 addDate 直接做水位线**：被否——与列表更新时间语义分叉正是要修复的问题。
