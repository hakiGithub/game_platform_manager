## 背景（Context）

L4D2 插件域内存在两个分裂的"插件商店"入口，交互形态都有问题（2026-09-11 用户报告"插件页面点击插件商店的弹窗太不好"）：

1. **内置插件市场是 960px 弹窗**（`Plugins.vue` 的 `showBuiltinDialog`）：搜索、全选按钮组、分类折叠面板 + 多选表格 + 批量安装进度条全部塞进 `el-dialog`，安装中还会强制锁住弹窗（禁关闭、禁 ESC）。重交互内容塞弹窗，体验差。
2. **远端仓库商店是独立页面**（`/plugin-store`，GitHub 仓库插件，独立侧栏菜单）：与内置市场分裂，"找插件装"是同一个用户任务却要两个入口；详情用 50% 宽 `el-drawer` 弹出，打断浏览流。

## 决策（Decision）

### 决策 1：插件管理页改为三 Tab（术语见 CONTEXT.md「插件市场领域」）

`/plugins` 页面内部以 Tab 切换三个视图，市场不再弹窗：

- **已安装**：现有插件表格迁移入 tab；
- **内置插件**：内置插件市场从 `el-dialog` 迁入，成为常驻 tab；
- **远端仓库**：`/plugin-store` 页面并入，成为常驻 tab。

有先例：playtime 并入 player-stats 的 Tab、version 并入 server-info 折叠面板。

### 决策 2：删除独立"插件商店"菜单与路由

L4D2 后端 `getMenus` 声明删除"插件商店"菜单项，前端删除 `/plugin-store` 路由。否则出现"市场 tab + 独立商店菜单"双入口，改版意义打折。

### 决策 3：内置插件 tab 用"筛选 chips + 整页表格"

- 分类折叠面板改为筛选 chips（全部 / 必选 / 推荐 / 可选等），搜索 + 筛选 + 批量选择集中在页头；
- 保留多选表格形态：内置插件数量有限、字段少，表格信息效率高于卡片网格；
- 不采用卡片网格：无图标/截图字段，撑不起"逛"型市场视觉。

### 决策 4：安装/下载任务统一页内反馈，不锁页面

- 内置批量安装、远端下载均已异步化（提交任务中心），页面只展示任务进度；
- 统一"插件任务"反馈区置于页头下方（sticky）：进度条 + 可展开任务明细，任意 tab 发起均可见，切 tab 不丢进度；
- 去除"安装中强制锁弹窗"约束——用户切走不影响后台执行。

### 决策 5：已安装插件详情编辑抽屉

已安装 tab 点击行名打开详情抽屉：集中展示描述/大小/安装时间 + 操作（启停/删除/配置页跳转），把散落的行操作收拢，与内置/远端 tab 的详情交互语言一致。不做文件重命名（涉及 SourceMod 加载逻辑）；显示名如需要可存插件本地元数据（后续增强）。

### 决策 6：远端仓库 tab 详情改行内展开

原 50% `el-drawer`（README + 文件列表）改为表格**行内展开**：三 tab 均为表格形态，交互统一；展开区内部滚动，高度可控。

### 决策 7：跨 tab 已安装标识按名称匹配（前端）

内置/远端 tab 标识"已安装"的匹配规则：插件名去 `.smx` 后缀、忽略大小写、忽略下划线/连字符差异后精确相等。

- 列表默认显示全部，已安装项打"已安装"角标；筛选 chips 含 全部 / 未安装 / 已安装，默认"全部"；
- 不隐藏已安装项（隐藏会让用户困惑商店里有没有该插件）；
- 若发现远端名（GitHub 仓库）与本地 `.smx` 文件名匹配率低，升级为后端在 VO 直接返回 `installed` 字段（后端小改，不阻塞本次）。

## 备选方案（Alternatives）

| 方案 | 描述 | 否决理由 |
|------|------|---------|
| 市场独立成新路由页 | 按钮改跳转 | "管理 + 装插件"同一语境被拆开；多一个菜单项 |
| 只去弹窗、两商店维持两入口 | 内置市场 tab 化，远端商店留独立菜单 | "找插件装"是同一任务，双入口是当前最大交互混乱源 |
| 内置市场卡片网格 | 分类色块 + 勾选卡片 | 无图标/截图字段，视觉撑不起来；表格信息效率更高 |
| 安装中锁页面/弹窗 | 沿用强制锁 | 安装已异步化，锁页面是弹窗时代的旧约束 |
| 远端详情保留抽屉 | 只换皮 | 50% 抽屉盖屏打断浏览流；行内展开与三 tab 表格形态统一 |
| 已安装项默认隐藏 | 默认只看未安装 | 用户无法确认商店是否收录某插件；角标 + 筛选 chips 更透明 |
| 已安装 tab 行内重命名 | 直接改 .smx 文件名 | SourceMod 按文件名加载，重命名破坏加载与依赖引用 |
