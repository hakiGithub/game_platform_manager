# 游戏服务器统一管理平台 UI/UE 全链路设计方案
完全对齐需求文档V1.0规范，贴合个人自用轻量运维场景，严格遵循「轻量优先、体验统一、安全兜底、插件化扩展」核心原则，覆盖MVP全流程交付要求。

---

## 一、设计总纲与核心原则
### 1.1 设计定位
面向个人游戏服运维场景的轻量型管理后台，以「**高频操作效率最大化、全流程闭环反馈、低视觉疲劳、强扩展兼容**」为核心，拒绝过度设计，100%对齐Element Plus原生规范，保证插件与原生体验无感知差异。

### 1.2 强制遵循的核心设计规则
| 规则类别 | 核心要求 | 对齐文档规范 |
|----------|----------|--------------|
| 轻量优先 | MVP阶段仅实现核心功能页面，非核心能力仅预留扩展插槽，无冗余设计 | 1.2节核心设计原则 |
| 体验统一 | 所有页面/插件页面100%复用Element Plus组件、全局样式、交互逻辑，禁止私自修改基础组件样式 | 4.3节设计规范 |
| 安全兜底 | 所有高危操作必须有二次确认+不可逆提示，全操作留痕，敏感操作强制校验 | 1.2节安全兜底原则 |
| 最短路径 | 核心高频操作（启停实例、部署、查看日志、配置修改）1-2次点击可达，无多层跳转 | 运维场景效率诉求 |
| 状态优先 | 主机/实例核心状态用「颜色+图标+文字」三重标识，全局实时同步，一眼可辨 | 运维场景核心诉求 |

## 二、全局设计规范
### 2.1 布局框架规范
严格采用需求文档指定的「**固定侧边栏+顶部导航+内容区**」经典管理后台布局，适配1920*1080、1366*768主流桌面分辨率，全页面布局统一。

| 布局模块 | 尺寸规范 | 核心职责 |
|----------|----------|----------|
| 左侧侧边栏 | 固定宽度240px，折叠后64px，可全局切换 | 一级导航菜单、插件注册的全局菜单插槽，菜单层级最多2级 |
| 顶部导航栏 | 固定高度64px，通栏布局 | 左侧面包屑导航，右侧用户信息、全局刷新、操作日志入口、全局配置入口 |
| 内容区 | 12栅格系统，统一内边距24px，卡片间距16px | 页面核心内容渲染，全页面采用卡片式设计，禁止无容器的零散内容 |
| 底部状态栏 | 高度32px，可选展示 | 平台版本号、全局连接状态、刷新间隔配置 |

### 2.2 视觉与主题规范
1.  **主题体系**：基于Element Plus官方CSS变量构建，默认提供「浅色运维主题（默认）」「深色低疲劳主题」两套方案，所有色值、圆角、间距、字体均通过CSS变量定义，插件可直接复用，无需单独适配。
2.  **核心色值规范**：100%对齐Element Plus原生规范，禁止私自修改
    - 主色：`#409EFF`（沉稳蓝，适配运维场景）
    - 成功色：`#67C23A`（运行中/在线/操作成功）
    - 警告色：`#E6A23C`（部署中/资源预警）
    - 危险色：`#F56C6C`（异常/离线/高危操作）
    - 信息色：`#909399`（已停止/次要信息）
3.  **状态视觉规则**：
    - 运行中/在线：绿色图标+文字，行背景无特殊处理
    - 已停止/离线：灰色图标+文字，整行不透明度降低至70%
    - 异常/故障：红色图标+文字，整行浅红色背景高亮
    - 执行中/部署中：蓝色加载动画+黄色进度提示，按钮置灰禁止重复操作
4.  **字体与间距规范**：
    - 字体：默认使用系统无衬线字体，标题16px/加粗，正文14px/常规，辅助文字12px/常规
    - 间距：全局统一使用8px基准网格，内边距、外边距均为8px的倍数，禁止零散数值

### 2.3 全局交互规范
1.  **操作闭环规则**：
    - 同步操作：点击有按压态，成功后3秒自动消失的Message提示，失败后常驻Notification提示，明确错误原因
    - 异步操作（部署/备份/大文件上传）：全局顶部进度条+实时阶段反馈，完成后弹窗提示，失败后展示错误日志+一键清理残留入口
    - 所有按钮点击后立即进入加载态，禁止重复点击，操作完成后恢复原状
2.  **高危操作兜底规则**（严格执行，无例外）：
    - 适用范围：停止实例、卸载实例、删除主机、还原备份、删除文件、执行高危自定义命令
    - 强制流程：点击按钮 → 二次确认弹窗（明确标注「不可逆操作」）→ 必须输入对应实例/主机/备份名称确认 → 执行操作 → 操作结果全量录入操作日志
    - 视觉强化：高危按钮使用红色边框/填充样式，放在操作列最末端，与常规操作按钮隔离
3.  **实时刷新规则**：
    - 主机/实例状态、资源使用率、在线玩家数默认30秒自动刷新，支持用户自定义刷新间隔
    - 操作执行后立即触发局部刷新，无需用户手动刷新全页面
4.  **表单与校验规则**：
    - 所有表单项左对齐标签，输入框占满剩余宽度，必填项标*，实时校验，错误提示直接展示在表单项下方
    - 端口配置自动校验主机占用情况，冲突即时标红拦截，禁止提交
    - 所有用户输入自动做安全转义，杜绝命令注入风险

## 三、核心模块页面设计（MVP全功能覆盖）
### 3.1 系统管理与鉴权模块
#### 3.1.1 登录页
- 极简居中布局，仅保留「用户名+密码」输入框、「记住我」选项、登录按钮，底部展示平台名称与版本号，无冗余内容
- 交互：输入实时校验，登录失败明确提示错误原因，会话超时自动跳转回登录页，对齐JWT鉴权规范
- 视觉：低饱和度背景，避免视觉疲劳，100%使用Element Plus原生组件

#### 3.1.2 控制台首页（Dashboard）
个人自用核心概览页，把用户最关心的信息全部前置，减少跳转路径，布局如下：
1.  顶部资源概览行（4张卡片，单张占6栅格）：主机总数/在线数、游戏实例总数/运行中数、异常实例数、备份总数，数字点击直接跳转到对应列表页
2.  中间数据行（左12栅格+右12栅格）：
    - 左侧：主机资源Top5卡片，展示CPU/内存/磁盘使用率最高的5台主机，进度条可视化，超80%阈值标红
    - 右侧：实例状态统计饼图，直观展示运行中/已停止/异常实例占比
3.  下半部分核心操作区（24栅格）：实例运行状态列表，直接展示实例核心信息+启停/重启操作按钮，无需进入详情页即可完成高频操作
4.  底部辅助区（24栅格）：最近10条操作日志，快速回溯操作记录

#### 3.1.3 全局配置页
采用标签页（Tabs）分模块布局，每个标签页为独立表单，底部统一保留「保存」「重置」按钮，每个配置项附带说明文字：
1.  平台基础配置：平台名称、刷新间隔、会话超时时间、主题默认配置
2.  SSH全局配置：连接超时时间、保活间隔、重试次数
3.  Docker全局配置：镜像源配置、超时时间、全局卷挂载规则
4.  游戏元数据管理：表格展示所有已加载的游戏元数据，列：游戏名称、支持的部署方式、默认端口、操作（查看配置、刷新元数据、上传YAML文件），支持上传YAML文件零代码新增游戏适配，上传后自动校验格式，错误明确提示

#### 3.1.4 插件管理页
- 顶部操作栏：上传插件、刷新插件列表
- 核心内容：插件列表表格，列：插件名称、版本、描述、状态（启用/禁用）、安装时间、操作（启用/禁用、卸载、查看详情）
- 插件详情弹窗：展示插件完整信息、注册的扩展点（Tab/菜单/按钮）、作者、更新日志，预留插件自定义内容插槽
- 交互：启用/禁用二次确认，卸载强二次确认，上传插件自动校验格式，操作后实时刷新列表

#### 3.1.5 操作日志页
- 顶部检索栏：操作时间范围、操作内容关键词、操作结果筛选（成功/失败）
- 核心内容：日志表格，列：操作时间、操作人、操作内容、操作结果、IP地址、详情查看
- 详情弹窗：展示操作完整参数、请求结果、错误信息，支持导出单条/全量日志

### 3.2 主机纳管模块
#### 3.2.1 主机列表页（核心页）
- 顶部操作栏：新增主机、刷新列表、批量操作（预留二期）
- 核心表格列（按优先级排序）：
  1.  状态：颜色+图标+文字，一眼识别在线/离线/异常
  2.  主机名称/备注、IP地址、SSH端口、操作系统
  3.  资源使用率：CPU/内存/磁盘进度条，超阈值标红
  4.  操作列：Web SSH（高频操作前置）、编辑、端口扫描、删除
- 核心交互：
  - 新增主机弹窗：必填项（主机名称、IP、SSH端口、用户名、密钥），强制「连接测试」，测试成功后方可保存
  - 删除主机：强二次确认，提示「删除主机将移除该主机下所有实例的管理权限，实例不会被卸载」，必须输入主机名称确认
  - 端口扫描：点击后发起扫描，弹窗展示主机所有占用端口、对应进程，支持筛选
  - 离线主机整行置灰，禁止发起运维操作，hover提示离线原因

#### 3.2.2 主机详情页
- 顶部头部：主机状态大标识、基础信息卡片（IP、操作系统、配置、运行时间）
- 标签页布局：
  1.  概览Tab：主机资源监控时序图（CPU/内存/磁盘/网络）、最近操作日志
  2.  实例列表Tab：该主机下所有游戏实例，与全局实例列表操作逻辑完全一致
  3.  端口管理Tab：端口扫描结果列表，支持手动刷新
  4.  Web SSH Tab：集成xterm.js终端，无需跳转新页面，支持全屏、清屏、快捷键

#### 3.2.3 Web SSH终端页
- 全屏终端布局，顶部主机快速切换下拉框，右侧全屏/清屏/断开连接按钮，主体终端占满剩余空间
- 支持快捷键复制粘贴、会话历史记录、断开自动重连，对齐需求文档基础终端能力要求

### 3.3 部署引擎模块
核心采用**4步分步部署向导**，屏蔽不同部署方式的底层差异，全流程校验+实时反馈，对齐标准化适配原则。
- 入口：主机列表「部署游戏」按钮、实例列表「新建实例」按钮，统一进入向导
- 支持随时切换上一步，已填写内容不丢失，每一步实时校验，不满足条件无法进入下一步

#### 步骤1：选择目标主机
- 内容：在线主机列表表格，仅可选择在线主机，选中后展示主机基础配置、资源使用率，自动校验是否满足游戏最低配置要求（从元数据读取）
- 强制校验：必须选中1台在线主机，方可进入下一步

#### 步骤2：选择游戏与部署方式
- 左侧：游戏列表，展示所有已加载元数据的游戏，带图标、名称、支持的部署方式
- 右侧：选中游戏的详情、支持的部署方式选项（LinuxGSM/Docker/Docker Compose，按元数据配置展示），选中后展示对应部署方式的说明、默认配置
- 强制校验：必须选中游戏+对应部署方式，方可进入下一步

#### 步骤3：配置实例参数
- 核心逻辑：基于选中的游戏+部署方式，通过元数据config_schema自动生成可视化表单，零代码适配
- 表单分区：
  1.  基础配置：实例名称（全局唯一，必填）、端口号（自动填充默认值，实时校验主机端口占用，冲突即时拦截）
  2.  部署配置：按部署方式自动生成对应表单
      - LinuxGSM：安装路径、启动参数、自动更新配置
      - Docker：镜像名称、环境变量、端口映射、卷挂载配置
      - Docker Compose：compose文件在线编辑器/上传入口，支持语法高亮
  3.  游戏配置：基于元数据自动生成可视化表单，如服务器名称、最大玩家数、密码等，每个配置项附带说明、默认值、校验规则
- 兜底方案：无元数据配置的游戏，提供「高级配置」入口，支持手动编辑配置文件、自定义启动参数
- 强制校验：所有必填项填写完成、端口无冲突、配置符合规则，方可进入下一步

#### 步骤4：预校验与确认部署
- 内容：前三步配置信息汇总确认，自动执行预部署校验（环境依赖校验、端口二次校验、资源占用校验），缺少依赖自动提示是否一键安装
- 底部操作：「开始部署」按钮，点击后关闭向导，跳转到实例列表，同时触发全局部署进度反馈
- 部署过程反馈：实时展示部署阶段（环境准备→依赖安装→资源下载→部署配置→启动实例→健康检查），部署成功弹窗提示，失败展示错误日志+一键清理残留资源入口，完全对齐需求文档部署流程控制要求

### 3.4 游戏实例生命周期管理模块
#### 3.4.1 实例列表页（核心高频页）
- 顶部操作栏：新建实例、刷新列表、多条件筛选（按主机/游戏/状态）
- 核心表格列（按优先级排序）：
  1.  状态：颜色+图标+文字，实时同步
  2.  实例名称、游戏名称、所属主机、IP/端口、在线玩家数/最大玩家数、运行时间
  3.  操作列：按实例状态动态展示高频操作按钮
      - 运行中：停止、重启、进入详情
      - 已停止：启动、卸载、进入详情
      - 异常：重启、查看日志、进入详情
      - 部署中：查看进度、取消部署
  4.  更多操作：配置管理、文件管理、备份、自定义命令
- 核心交互：
  - 状态实时刷新，不同状态行用对应背景色区分，一眼识别
  - 启停操作点击后立即进入加载态，全局通知反馈，状态实时更新
  - 卸载实例：强二次确认，提示「卸载将删除实例所有配置、进程、相关文件，无法恢复」，必须输入实例名称确认
  - 预留插件自定义按钮插槽，插件注册的按钮自动展示在操作列末端，与原生样式完全一致

#### 3.4.2 实例详情页（全功能运维核心页）
- 顶部头部栏：实例状态大标识、核心基础信息（实例名称、游戏、主机、IP/端口），右侧核心操作按钮（启停/重启/卸载），危险操作按钮隔离展示
- 标签页布局（原生Tab+插件扩展插槽）：
  1.  **概览Tab**：实例基础信息卡片（进程PID、运行时间、部署方式、安装路径、健康状态）、在线玩家列表、资源监控时序图、最近操作日志
  2.  **配置管理Tab**：
      - 优先可视化表单：与部署向导一致，基于元数据自动生成，支持修改、保存、重启生效
      - 兜底配置文件编辑：配置文件列表，选中后在线编辑，支持多格式语法高亮、上传/下载，修改后提示重启生效
      - 预留插件自定义区块插槽，插件注册的表单区块自动展示在原生区块下方，样式完全统一
  3.  **文件管理Tab**：基于SFTP的可视化文件管理器
      - 左侧目录树，右侧文件列表，顶部操作栏（上传、新建文件夹、刷新、返回上级）
      - 支持拖拽上传、大文件进度展示、文本文件在线编辑、文件下载/重命名/删除
      - 自动定位到实例安装目录，删除文件/文件夹二次确认，完全对齐需求文档文件管理要求
  4.  **日志Tab**：实时日志查看器
      - 顶部日志文件切换下拉框，右侧刷新/清屏/自动滚动开关/下载按钮
      - 日志区域支持语法高亮，错误标红、警告标黄，自动滚动到底部，支持关键词搜索
  5.  **自定义命令Tab**：
      - 顶部「新增自定义命令」按钮，下方命令卡片列表，每张卡片展示命令名称、内容、操作（执行/编辑/删除）
      - 新增/编辑弹窗：命令名称、Shell命令内容（支持实例路径/主机IP等变量）、执行说明、是否需要二次确认
      - 执行命令：弹窗实时展示输出内容，支持中断执行，执行结果全量录入操作日志
  6.  **插件扩展Tab插槽**：插件注册的Tab自动追加到原生Tab后方，与原生样式、交互完全一致，对齐需求文档实例详情Tab插槽要求

### 3.5 插件化扩展体系设计
完全对齐需求文档插件化规范，通过4个标准化插槽实现扩展，保证插件与原生体验无感知差异，核心设计如下：

#### 3.5.1 标准化扩展插槽规范
| 插槽名称 | 插入位置 | 扩展能力 | 设计约束 |
|----------|----------|----------|----------|
| 实例详情Tab插槽 | 实例详情页Tab栏 | 插件注册自定义Tab页（如GM工具、地图管理、Mod管理） | Tab名称≤4字，使用Element Plus内置图标，页面布局必须与原生完全一致 |
| 全局侧边栏菜单插槽 | 左侧侧边栏原生菜单后方 | 插件注册全局一级/二级菜单，跳转插件独立页面 | 菜单样式、交互与原生完全一致，插件页面必须复用全局布局与样式 |
| 实例列表操作插槽 | 实例列表操作列原生按钮后方 | 插件注册自定义操作按钮，支持按实例状态动态显示 | 按钮样式、尺寸、交互与原生完全一致，禁止使用自定义样式 |
| 实例配置页区块插槽 | 实例配置管理Tab原生区块下方 | 插件注册自定义表单区块，实现专属配置能力 | 区块使用原生卡片样式，表单控件完全对齐全局规范 |

#### 3.5.2 插件UI强制规范
1.  插件必须100%复用主应用全局CSS变量、Element Plus组件，禁止私自引入第三方UI库、修改全局样式
2.  插件所有页面必须遵循全局布局规范、间距规范、交互规范，用户无感知原生与插件的差异
3.  插件的弹窗、通知、加载态必须使用主应用封装的全局方法，禁止自定义样式
4.  插件所有操作必须全量录入平台操作日志，高危操作必须遵循全局二次确认规范

#### 3.5.3 分层扩展适配设计
对齐需求文档分层扩展方案，设计对应渲染能力：
- 零代码轻量扩展：通过YAML元数据配置，自动生成表单、列表、操作按钮，无需前端代码
- 中度扩展：自定义脚本绑定，自动生成操作按钮，支持执行反馈
- 深度扩展：独立插件开发，支持自定义Vue组件，主应用动态加载，共享全局能力

- 还原操作：强二次确认，提示「还原将覆盖当前实例对应文件/数据库，无法恢复」，必须输入备份名称+实例名称双重确认方可执行
- 交互：备份进度实时反馈，成功/失败明确提示，备份文件支持本地下载，删除备份二次确认

## 四、异常处理与兼容性设计
### 4.1 全局异常处理规范
1.  网络异常：请求失败自动重试3次，重试失败弹出提示，支持手动重试，页面状态不丢失
2.  主机离线：所有针对离线主机的操作，提前拦截并提示「目标主机离线，无法执行操作」，禁止发起请求
3.  实例状态异常：不符合状态的操作按钮直接置灰，hover提示禁止操作的原因
4.  操作失败：所有错误必须给出明确的可理解的原因，禁止通用的「操作失败」提示，同时附带解决方案建议

### 4.2 兼容性设计
1.  分辨率适配：12栅格布局自动适配1920*1080、1366*768等主流桌面分辨率，小分辨率下自动调整栅格占比、隐藏非核心表格列
2.  浏览器兼容：支持Chrome、Edge、Firefox等主流现代浏览器，对齐前端技术栈规范
3.  部署方式兼容：三种部署方式的操作逻辑完全统一，用户无需关心底层差异，对齐标准化适配原则
4.  Linux发行版兼容：自动适配apt/yum包管理器差异，用户无感知，对齐需求文档发行版兼容要求
