## 一、设计概述

### 1.1 设计原则

本模块严格遵循项目 UI/UE 设计规范，100% 复用 Element Plus 组件库，保证与现有系统视觉和交互体验的一致性。

| 设计原则 | 具体要求 |
|----------|----------|
| 轻量优先 | 仅实现需求文档定义的核心功能，无冗余设计 |
| 体验统一 | 100% 复用 Element Plus 组件、全局样式、交互逻辑 |
| 安全兜底 | 删除容器、强制删除镜像等高危操作强制二次确认 |
| 最短路径 | 容器启停、终端访问、日志查看等高频操作 1-2 次点击可达 |
| 状态优先 | 容器状态用「颜色+图标+文字」三重标识，全局实时同步 |

### 1.2 模块结构

```
Docker 管理模块
├── 独立 Docker 管理页面 (/docker)
│   ├── 主机选择器
│   ├── 容器列表 Tab
│   ├── 镜像列表 Tab
│   └── 容器详情页 (/docker/container/:id)
│
├── 实例详情页集成
│   └── 关联容器区域
│
└── 公共组件
    ├── 容器终端组件 (DockerTerminal)
    ├── 文件管理组件 (DockerFileManager)
    └── 日志查看组件 (DockerLogViewer)
```

## 四、交互流程说明

### 4.1 容器生命周期操作流程

#### 4.1.1 启动容器

```
用户点击「启动」按钮
    ↓
按钮进入加载状态
    ↓
调用 API: POST /api/docker/hosts/{hostId}/containers/{containerId}/start
    ↓
    ├── 成功 → Message 提示「容器启动成功」→ 刷新容器状态 → 按钮恢复
    └── 失败 → Notification 提示错误原因 → 按钮恢复
```

#### 4.1.2 停止容器

```
用户点击「停止」按钮
    ↓
弹出确认对话框
    ↓
    ├── 取消 → 关闭对话框
    └── 确认 → 按钮进入加载状态
                ↓
                调用 API: POST /api/docker/hosts/{hostId}/containers/{containerId}/stop
                ↓
                ├── 成功 → Message 提示「容器已停止」→ 刷新容器状态
                └── 失败 → Notification 提示错误原因
```

#### 4.1.3 删除容器（高危操作）

```
用户点击「删除」按钮
    ↓
弹出二次确认对话框
    ┌────────────────────────────────────────┐
    │  删除容器                               │
    │  ─────────────────────────────────────│
    │                                        │
    │  ⚠️ 此操作不可逆，将删除容器及其数据。   │
    │                                        │
    │  请输入容器名称确认: [              ]   │
    │                                        │
    │  [ ] 同时删除关联的卷                   │
    │                                        │
    │           [取消]  [确认删除]           │
    └────────────────────────────────────────┘
    ↓
用户输入容器名称
    ↓
    ├── 名称不匹配 → 禁用确认按钮
    └── 名称匹配 → 点击确认
                    ↓
                    按钮进入加载状态
                    ↓
                    调用 API: DELETE /api/docker/hosts/{hostId}/containers/{containerId}
                    ↓
                    ├── 成功 → Message 提示「容器已删除」→ 返回列表页
                    └── 失败 → Notification 提示错误原因
```

### 4.2 容器终端操作流程

```
用户进入终端 Tab
    ↓
自动建立 WebSocket 连接: /ws/docker/exec
    ↓
    ├── 连接成功 → 显示终端界面 → 用户可输入命令
    │               ↓
    │               用户输入命令 → 发送到后端 → 接收输出 → 显示结果
    │
    └── 连接失败 → 显示错误信息 → 显示重连按钮
                    ↓
                    点击重连 → 重新建立连接
```

### 4.3 文件上传流程

```
用户点击「上传」或拖拽文件
    ↓
弹出文件选择器（如果是拖拽则跳过）
    ↓
选择文件后开始上传
    ↓
显示上传进度条
    ┌────────────────────────────────────────┐
    │  上传中: config.json                    │
    │  [████████████░░░░░░░░░░░░] 45%        │

    └────────────────────────────────────────┘
    ↓
    ├── 上传成功 → Message 提示「文件上传成功」→ 刷新文件列表
    └── 上传失败 → Notification 提示错误原因
```

## 九、WebSocket 端点

### 9.1 容器终端

**端点**: `/ws/docker/exec`

**连接参数**:
```javascript
{
  hostId: number,
  containerId: string,
  shell: string,      // /bin/bash, /bin/sh
  cols: number,       // 终端列数

```

**消息格式**:
```javascript
// 客户端 -> 服务端
{
  type: 'input',
  data: 'ls -la\n'
}

// 客户端 -> 服务端 (resize)
{
  type: 'resize',
  cols: 120,
  rows: 30
}

// 服务端 -> 客户端
{
  type: 'output',
  data: 'total 24\ndrwxr-xr-x  5 root root 4096...'
}
```
