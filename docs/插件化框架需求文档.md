## 一、项目背景

### 1.1 背景

游戏服务器管理平台需要支持多种游戏服务器的管理。不同游戏有不同的管理功能需求（如 L4D2 的地图管理、Minecraft 的模组管理等）。为了实现：

1. **解耦**：游戏特定功能与平台核心功能分离
2. **扩展性**：新增游戏支持无需修改主应用代码
3. **独立性**：插件可独立开发、测试、部署

需要设计并实现一套完整的插件化框架。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 主应用零改动 | 新增游戏插件时，主应用前后端无需任何代码修改 |
| 插件完全独立 | 插件包含后端 API 和前端页面，可独立开发部署 |
| 标准化规范 | 定义清晰的插件开发规范和接口规范 |
| 自动发现加载 | 主应用自动发现并加载插件 |

### 1.3 范围

本文档定义插件化框架的实现需求，**不包含具体游戏插件（如 L4D2）的实现**。

### 2.2 插件加载流程

```
主应用启动
    │
    ▼
扫描 plugins 目录
    │
    ▼
加载插件 JAR 包 (PF4J)
    │
    ▼
注册插件 API 路由
    │
    ▼
注册插件静态资源路由
    │
    ▼
插件就绪，等待前端请求
    │
    ▼
前端请求插件清单 → 返回 manifest.json
    │
    ▼
前端请求插件页面 → 返回 HTML/JS/CSS
```

### 2.3 前端加载流程

```
用户访问实例详情页
    │
    ▼
获取实例信息（包含 gameCode）
    │
    ▼
请求插件清单 GET /api/plugin/{gameCode}/manifest
    │
    ▼
动态渲染侧边栏菜单
    │
    ▼
用户点击插件菜单项
    │
    ▼
创建 iframe，加载插件前端页面
    │
    ▼
插件前端初始化，发送 READY 消息
    │
    ▼
主应用发送 INIT/AUTH 消息
    │
    ▼
插件页面渲染完成
```

#### FE-003：实现插件通信管理器

**输出**：
- `pluginCommunication.ts` - 通信管理器

**要求**：
```typescript
// 主应用端
export class PluginCommunicationManager {
  
  private iframe: HTMLIFrameElement
  private messageHandlers: Map<string, Function>
  
  constructor(iframe: HTMLIFrameElement) {
    this.iframe = iframe
    this.setupListener()
  }
  
  // 发送初始化消息
  sendInit(payload: InitPayload) {
    this.send('INIT', payload)
  }
  
  // 发送认证消息
  sendAuth(payload: AuthPayload) {
    this.send('AUTH', payload)
  }
  
  // 发送主题变化消息
  sendThemeChange(payload: ThemePayload) {
    this.send('THEME_CHANGE', payload)
  }
  
  // 处理插件消息
  private handleMessage(event: MessageEvent) {
    const { type, payload } = event.data
    switch (type) {
      case 'READY':
        this.handleReady()
        break
      case 'NAVIGATE':
        this.handleNavigate(payload)
        break
      case 'NOTIFY':
        this.handleNotify(payload)
        break
      case 'CONFIRM':
        this.handleConfirm(payload)
        break
    }
  }
}
```

#### FE-004：定义消息类型规范

// 主应用 → 插件
interface InitMessage {
  type: 'INIT'
  payload: {
    instanceId: number
    instanceName: string
    gameCode: string
    hostId: number
    hostIp: string
    deployPath: string
    ports: Record<string, number>
  }
}

interface AuthMessage {
  type: 'AUTH'
  payload: {
    token: string
    user: {
      id: number
      username: string
      role: string
      permissions: string[]
    }
  }
}

interface ThemeChangeMessage {
  type: 'THEME_CHANGE'
  payload: {
    isDark: boolean
  }
}

// 插件 → 主应用
interface ReadyMessage {
  type: 'READY'
  payload: {}
}

interface NavigateMessage {
  type: 'NAVIGATE'
  payload: {
    path: string
    query?: Record<string, string>
  }
}

interface NotifyMessage {
  type: 'NOTIFY'
  payload: {
    type: 'success' | 'warning' | 'error' | 'info'
    title: string
    message: string
    duration?: number
  }
}

interface ConfirmMessage {
  type: 'CONFIRM'
  payload: {
    requestId: string
    title: string
    message: string
    confirmText?: string
    cancelText?: string
  }
}

interface ConfirmResultMessage {
  type: 'CONFIRM_RESULT'
  payload: {
    requestId: string
    result: boolean
  }
}

#### 5.1.2 插件静态资源 API

```
GET /plugin/{gameCode}/ui/{resourcePath}

Path Parameters:
  - gameCode: 游戏代码
  - resourcePath: 资源路径，如 index.html、assets/index.js

Response:
  - 成功：返回资源内容，设置正确的 Content-Type
  - 失败：404 Not Found

Content-Type 映射：
  - .html → text/html
  - .js → application/javascript
  - .css → text/css
  - .png → image/png
  - .jpg/.jpeg → image/jpeg
  - .svg → image/svg+xml
  - .woff/.woff2 → font/woff2
  - 其他 → application/octet-stream

Cache-Control: max-age=604800 (7天)
```

### 5.2 前端通信规范

#### 5.2.1 消息格式

```typescript
interface Message {
  type: string           // 消息类型
  payload: any           // 消息负载
  timestamp?: number     // 时间戳（可选）
}
```

#### 5.2.2 消息类型汇总

| 方向 | 类型 | 说明 | payload |
|------|------|------|---------|
| 主应用→插件 | INIT | 初始化实例信息 | `{ instanceId, gameCode, ... }` |
| 主应用→插件 | AUTH | 认证信息 | `{ token, user }` |
| 主应用→插件 | THEME_CHANGE | 主题变化 | `{ isDark }` |
| 插件→主应用 | READY | 插件就绪 | `{}` |
| 插件→主应用 | NAVIGATE | 请求导航 | `{ path, query }` |
| 插件→主应用 | NOTIFY | 显示通知 | `{ type, title, message }` |
| 插件→主应用 | CONFIRM | 显示确认框 | `{ requestId, title, message }` |
| 主应用→插件 | CONFIRM_RESULT | 确认结果 | `{ requestId, result }` |

## 十、风险与注意事项

### 10.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| iframe 跨域问题 | 插件页面无法加载 | 确保静态资源服务正确配置 CORS |
| postMessage 安全 | 恶意消息攻击 | 验证消息来源 origin |
| 插件 ClassLoader 隔离 | 类冲突 | 使用 PF4J 的类加载隔离机制 |
| 插件内存泄漏 | 应用崩溃 | 插件停止时清理资源 |

### 10.2 注意事项

1. **插件版本兼容**：插件需要声明兼容的主应用版本
2. **插件权限控制**：插件的 API 访问需要进行权限校验
3. **插件热加载**：生产环境谨慎使用热加载，可能导致状态丢失
4. **前端资源缓存**：使用 hash 文件名，确保缓存正确更新
